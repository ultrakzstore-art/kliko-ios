# Kliko iOS

Приложение Kliko для iPhone: сайт `kliko.kz` в нативной оболочке плюс то, чего сайт не
умеет — пуши при закрытом приложении, плашка сделки на локскрине, прелоадер, экран без
связи, работа с камерой и микрофоном.

Отдельный репозиторий, **вне** веб-репо `ultra-site`: Swift не должен уезжать на
прод-сервер через `git push hoster`.

## Что это, устройство

**Оболочка, а не второй интерфейс.** В июле 2026 нативные экраны (лента, карточка,
вход, чат) были написаны и затем удалены — держать вторую реализацию витрины и чата
значит чинить каждую правку дважды. Код остался в истории (`387e7ca`), подход и
эндпоинты валидны, если решение когда-нибудь пересмотрят.

Сейчас:

| Слой | Что делает |
|---|---|
| `Sources/Web/WebContainer.swift` | WKWebView: cookie-сессия как в браузере, pull-to-refresh, свайп-назад, гранты камеры и микрофона, `tel:` / WhatsApp / Telegram наружу, оплата и eGov остаются внутри |
| `Sources/Web/SplashView.swift` | прелоадер с логотипом, минимальное время показа |
| `Sources/Web/WebBridge.swift` | мост JS ↔ Swift: токен APNs, `window.KlikoLive`, `window.KlikoNative` |
| `Sources/App/AppDelegate.swift` | регистрация в APNs, deep-link по тапу на пуш |
| `Sources/LiveActivity/` + `WidgetSources/` | Live Activity сделки: локскрин и Dynamic Island |

Веб-часть моста живёт в `ultra-site`: `inc/app_bridge.php` (отдаёт `window.KlikoUser`
и `window.KlikoCsrf`), `api/push_register.php` (приём токена APNs), `inc/apns.php`
(отправка), `js/cabinet.js` → `dealLiveActivity()` (кормит плашку сделки).

Как устроен этап 1:

- Лента (`NativeFeedView`) лежит поверх веб-обёртки и заменяет веб-главную. Страница под
  ней грузится как раньше — ради сессии, пушей и плашки сделки.
- Данные — `GET /api/listings.php` (контракт первой нативной ленты, `8080f85`), **с куками
  веб-сессии**: город и вход живут в сессии сайта.
- Нажали карточку — объявление открывается страницей сайта; страница ушла на главную — снова
  лента (обёртка следит за адресом).
- API ответил не тем — на экране ошибки есть «Открыть сайт», и приложение остаётся веб-обёрткой
  до следующего запуска. Совсем выключить ленту — `Config.нативнаяЛента = false`.
- Карточка (этап 2) открывается из ленты сразу с тем, что известно по ленте, и дотягивает
  полную по `GET /api/listings.php?id=`. Чат, безопасная сделка и оплата — пока на сайте:
  кнопка «Написать или купить» открывает страницу объявления в обёртке. Рубильник —
  `Config.нативнаяКарточка`.
- Чат (этап 3) — `dm.php` с куками веб-сессии: list/poll читают, open/send пишут и несут CSRF
  страницы (`window.KlikoCsrf`, как регистрация пушей). Вход в чат — значок в шапке ленты.
  🔴 Отправка включена для проверки на живом сайте (`Config.нативныйЧатОтправка = true`): не
  проверено, что `dm.php` принимает запись с куками, а не только с bearer-токеном июльской
  версии. Не ушло — под полем ввода код причины (`auth/csrf`, `HTTP 403`, ответ сайта). Не
  заработает — `false`: переписка читается в приложении, ответ пишется на сайте.
- Нижние вкладки (этап 4) — только на нативных экранах: у страниц сайта своя нижняя навигация,
  и вторая над ней была бы лишней. «Кабинет» и «Разместить» открывают страницы сайта, выбранной
  остаётся прежняя вкладка; «Главная» сайта возвращает в ленту. Вкладка «Разместить» появится,
  когда в `Config.адресПодачи` будет адрес страницы подачи. Рубильник — `Config.нижниеВкладки`.
- Избранное (этап 5) — на телефоне: API избранного на сайте приложению неизвестно, поэтому сердечко
  кладёт снимок объявления (цена, обложка, город) в файл в Application Support вне резервной копии,
  до 500 штук, и стирается при выходе из аккаунта вместе с лентой. Открыли карточку — цена в избранном
  освежается. Вкладка между Лентой и Сообщениями; без нижних вкладок — сердечко в шапке ленты.
  Рубильник — `Config.избранное`.
- Недавнее (этап 6) — тоже на телефоне, одним файлом в Application Support вне резервной копии:
  открытая карточка ложится наверх полосы «Вы смотрели» над разделами ленты (до 30, повтор
  поднимается, а не дублируется), отправленный поиск — в историю (до 10, без повторов с точностью
  до регистра), которая показывается подсказками под пустым полем. Стирается при выходе из
  аккаунта. Рубильник — `Config.недавние`.
- Похожие (этап 7) — та же `GET /api/listings.php` с `cat=<раздел объявления>` и `per=12`, своей
  задачей, не задерживая карточку: без самого объявления и объявлений чужого раздела, до 10.
  Раздела нет, запрос не прошёл или пусто — полосы нет. На телефон не пишется. Рубильник —
  `Config.похожие`.
- Ссылки (этап 8) — входы снаружи (тап по пушу, `kliko://open?u=`, универсальная ссылка) идут через
  `WebBridge.открытьСнаружи`: `/marketplace?item=<номер>` открывает нативную карточку во вкладке «Лента»
  (полную она дотягивает по `?id=`), `/cabinet.php?s=messages` — вкладку «Сообщения». Адрес с другими
  параметрами или якорем, чужие страницы и переходы изнутри приложения («Написать или купить») — сайтом,
  как раньше. Работает при нижних вкладках. Рубильник — `Config.нативныеСсылки`.
- Кабинет (этап 9) — вкладка «Кабинет» стала экраном настроек: вошёл ли человек (`window.KlikoUser`
  загруженной страницы, без имени), вход по Face ID (`AppLock`), статус уведомлений, очистка кэша, избранного
  и истории с подтверждением, версия. Кабинет, вход и выход — страницами сайта: выход там закрывает серверную
  сессию и снимает пуши. На телефон экран ничего не пишет. Рубильник — `Config.нативныйКабинет`.
- Система (этап 10) — открытая карточка ложится в поиск iPhone (Core Spotlight, домен `kz.kliko.listing`,
  на 30 дней); нажатие на результат идёт как ссылка `/marketplace?item=` через `WebBridge.открытьСнаружи`.
  Индекс стирается при выходе из аккаунта и вместе с «Вы смотрели». Та же карточка — активность Handoff
  (`NSUserActivityTypeBrowsingWeb`): на Mac и iPad объявление продолжается в Safari. Быстрые действия с иконки
  задаются из кода при запуске и идут через роутер этапа 8 (`WebBridge.открытьЭкран`): «Поиск» открывает ленту
  с полем поиска в фокусе. Рубильники — `Config.spotlight`, `Config.handoff`, `Config.быстрыеДействия`.
- Загрузка, доступность и значок (этап 11) — пустая лента грузится серыми карточками той же сетки (сама `ListingCard`
  под `.redacted`, мерцание по `TimelineView`, без него при «Уменьшении движения»). VoiceOver читает карточку фразой
  «название, цена, город» с метками ТОП и «новое», сообщение — «Вы: …» или «<собеседник>: …» со временем; фото —
  украшение. Шрифты карточки растут с «Размером текста», при крупном для доступности сетка — в одну колонку. Число
  непрочитанных из `dm.php list` ставится на иконку (`setBadgeCount`), только если наклейки разрешены, и снимается при
  выходе. Рубильники — `Config.скелетЛенты`, `Config.значокНепрочитанных`.
- Сохранённые поиски (этап 12) — колокольчик над выдачей (и в шапке ленты: её iPhone прячет, пока открыт поиск), пока в
  ленте поиск или раздел, сохраняет его на телефоне
  (Application Support вне резервной копии, до 20, без повторов с точностью до регистра); список со свайпом «Удалить» — в
  кабинете. Фоновое задание `BGAppRefreshTask` `kz.kliko.app.saved-search` (`UIBackgroundModes: fetch` и
  `BGTaskSchedulerPermittedIdentifiers` в `project.yml`) ставится при уходе в фон и после каждого запуска, не раньше чем
  через час: берёт первую страницу той же `GET /api/listings.php` по каждому поиску с куками веб-сессии (WebKit не
  ответил за 5 с — без них), сверяет номера с виденными и присылает одно локальное уведомление, только если уведомления
  разрешены. Нажатие (метка `kliko_local` в `userInfo`, пуши сайта идут по `url` как раньше) ведёт через роутер этапа 8
  в ленту с этим поиском. 🔴 Лента сортирована «рекомендациями» (`sort=reco`): «новое» — не виденное этим поиском, а не
  только что поданное. Стирается при выходе. Рубильник — `Config.сохранённыеПоиски`.
- Объявления без сети (этап 13) — ответ `GET /api/listings.php?id=` целиком (`{ok, item}`) ложится файлом на объявление
  в папку Application Support вне резервной копии (`ListingDetailCache`), если объявление в избранном или открыто (то есть
  в «Вы смотрели»); до 60 файлов, копии снятых с избранного и вычищенных из недавнего уходят через 2 с. Нет связи или
  сайт ответил 5xx — карточка показывает копию с пометкой «Сохранённая копия · когда» и «Повторить»; 404 и прочие ответы
  сайта копией не подменяются, а цена в избранном и «Вы смотрели» копией не переписывается. Сердечко на неоткрытом
  объявлении один раз скачивает его карточку в фоне — по одному запросу за раз, без повторов. Стирается при выходе.
  Рубильник — `Config.карточкиБезСети`.
- iPad (этап 14) — в широком окне (`horizontalSizeClass == .regular`) вкладка «Лента» — `NavigationSplitView`: слева та же
  лента (колонка ~400 pt, адаптивная сетка), справа выбранное объявление со своим стеком (похожие, чат) или «Выберите
  объявление». Карточки, «Вы смотрели» и ссылка из пуша (этап 8) выбирают объявление, а не уводят с ленты. iPhone и узкое
  окно iPad (Split View, Slide Over) — прежний стек: выбранное ложится в него и, если окно снова расширили, возвращается
  в правую колонку. Рубильник — `Config.айпадДвеКолонки`.
- Тема оформления (этап 15) — раздел «Оформление» в кабинете: «Системная», «Светлая» или «Тёмная». Выбор ставится окну
  (`UIWindow.overrideUserInterfaceStyle`), и от него тему берут SwiftUI, системные окна и страница сайта (`WKWebView` без
  своей темы → `prefers-color-scheme`); часы на системном фоне решаются по теме окна, а не iPhone. Хранится в `UserDefaults`
  и при выходе не стирается — это настройка телефона. Рубильник — `Config.выборТемы`.
- «Что нового» и оценка (этап 16) — при первом запуске новой версии (`CFBundleShortVersionString` против записанной в
  `UserDefaults`; на первой установке только записываем) над нативным слоем, когда он на экране и замка Face ID нет,
  всплывает лист с включёнными рубильниками возможностями и «Понятно»; тот же список — строкой «Что нового» в кабинете.
  Окно оценки (`@Environment(\.requestReview)`) — после третьего объявления в избранном или закрытой пятой карточки в
  этой версии: не чаще раза в версию, не раньше трёх дней после установки, не над сайтом, не под замком и не поверх
  листа (`presentedViewController`). Покажет ли окно, решает iOS. Номера посчитанных объявлений стираются при выходе.
  Рубильники — `Config.чтоНового`, `Config.просьбаОценить`.
- Удобство чата (этап 17) — черновик переписки хранится по номеру диалога (`tid`) одним JSON в Application Support вне
  резервной копии (до 30 диалогов): возвращается в поле при открытии, стирается, когда сообщение ушло, и при выходе.
  🔴 Только на телефоне — черновиков у `dm.php` нет. Прокрутили вверх — внизу справа кнопка «вниз» (видна ли нижняя
  отметка, знает `onAppear`/`onDisappear` в ленивом стеке: `onScrollGeometryChange` — только с iOS 18), новые
  сообщения собеседника тогда не везут вниз, а считаются на кнопке; поле ввода в фокусе — человек в конце переписки, низ
  держится и при выезде клавиатуры, и с новыми сообщениями. Долгое нажатие на текстовое сообщение —
  «Копировать» (и действием VoiceOver); «потяни — обновится» — один внеочередной `poll`, опрос раз в 3 с прежний.
  Рубильник — `Config.удобныйЧат`.
- Уточнение ленты (этап 18) — «Уточнить» первым чипом в полосе разделов открывает лист: город (`Picker` из городов
  загруженных объявлений и «Любой»), цена от и до (та же, что на карточке: у аренды — за сутки; без цены при заданной
  границе — не подходит), «Только новые», «Сбросить». 🔴 Отбор — только по `FeedModel.items`, для показа: какие фильтры
  понимает `api/listings.php`, кроме `cat` и `q`, приложению неизвестно, поэтому и в листе, и на чипе над сеткой сказано
  «Уточнено по загруженным: N из M». Подгрузка работает: следующую страницу просит и последняя видимая карточка, и
  отметка под сеткой (`task(id:)` по числу загруженного) — не больше трёх пустых подгрузок подряд, дальше «Искать

## Сборка — в облаке, Mac не нужен

Сборку делает GitHub Actions на macOS-раннере: `.github/workflows/ios.yml`. Подпись —
ключом App Store Connect API, сертификат и профили Xcode создаёт сам
(`-allowProvisioningUpdates`). Ни сертификатов, ни fastlane match, ни своего Mac.

### 1. В кабинете Apple (браузер, Windows подходит)

1. **Identifiers** → App ID `kz.kliko.app`, включить **Push Notifications**.
   Второй App ID `kz.kliko.app.widgets` — для виджета Live Activity.
2. **Keys** → новый ключ с **APNs** → скачать `AuthKey_XXXX.p8` (даётся **один раз**),
   записать **Key ID**. Это ключ для отправки пушей с сервера.
3. **Team ID** — правый верхний угол портала.
4. **App Store Connect → Users and Access → Integrations → App Store Connect API** →
   ключ с ролью **App Manager**: **Issuer ID**, **Key ID**, файл `.p8`.
   Это отдельный ключ, не тот, что для APNs: первый подписывает и заливает сборку,
   второй шлёт уведомления.
5. **App Store Connect → Apps** → создать приложение с bundle id `kz.kliko.app`.

### 2. Секреты репозитория

Settings → Secrets and variables → Actions:

| Секрет | Откуда |
|---|---|
| `APPLE_TEAM_ID` | Team ID из портала |
| `ASC_KEY_ID` | Key ID ключа App Store Connect API |
| `ASC_ISSUER_ID` | Issuer ID оттуда же |
| `ASC_KEY_P8` | тот `.p8` в base64, одной строкой |

В PowerShell на Windows:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("AuthKey_XXXX.p8"))
```

### 3. Запуск

Вкладка **Actions** → «iOS · TestFlight» → **Run workflow**.

Первый прогон — с `upload = false`: соберёт и подпишет, но никуда не отправит, и
покажет, всё ли на месте, не расходуя номер сборки в App Store Connect. Дальше
`upload = true` либо тег `v1.0.0` — сборка уезжает в TestFlight сама.

Номер сборки — номер запуска workflow, повторов не бывает. Версия витрины берётся из
тега (`v1.0.0` → `1.0.0`) или из поля при ручном запуске.

## Пуши: что задать на сервере

В `admin_config.php` (правится руками на сервере, в репозитории его нет):

```php
define('APNS_KEY_ID',   'XXXXXXXXXX');                  // Key ID ключа APNs
define('APNS_TEAM_ID',  'YYYYYYYYYY');                  // Team ID
define('APNS_BUNDLE_ID','kz.kliko.app');
define('APNS_KEY_P8',   '/абсолютный/путь/AuthKey_XXXXXXXXXX.p8');
define('APNS_ENV',      'production');
```

⚠️ **`APNS_ENV` и `aps-environment` в `project.yml` должны совпадать.** Сейчас в
проекте стоит `production` — под TestFlight и App Store. Расхождение не ломает
сборку: APNs просто отвечает `BadDeviceToken`, и пуши молча не доходят.

Файл `.p8` положить вне веб-корня и закрыть от раздачи.

## Локально на Windows

Собрать нельзя — нужен Xcode. Проверять правки можно только прогоном workflow.
Поэтому Swift здесь пишется с расчётом на первый успешный проход: синтаксис
выверяется глазами, а не компилятором.

```

  KlikoApp.swift                — @main → RootWebView

  App/AppDelegate.swift         — APNs, deep-link

  LiveActivity/DealActivityManager.swift

WidgetSources/DealLiveActivity.swift  — локскрин и Dynamic Island
```
