# «Подойдут ли?» — справочник посадки машин: что нужно от сервера

Документ для разработчика сайта kliko.kz (ultra-site). Просьба владельца (13.10.2026): «распиши примерочную; нужен ли
3D — очки, шины, диски?» → **«нужнее охват всего»**.

Настоящий 3D шинам и дискам не нужен: важны числа. У объявлений раздела «Шины и диски» (`tires-wheels`) на странице
объявления в приложении есть кнопка **«Подойдут ли?»** (хаб «Примерить / проверить», `Sources/Native/TryOn/TryOnHub.swift`).
Окно (`Sources/Native/TryOn/AutoFit*.swift`) **всё считает на телефоне**:

- разбирает параметры товара из характеристик объявления (`specs`) и названия: шины «225/45 R17», «225/45/17», сезон;
  диски «R17 5x114.3 ET45 DIA 67.1 7.5J» в любых написаниях (5×114,3; PCD; ЕТ; ЦО);
- сверяет с машиной человека: разболтовка (PCD), центральное отверстие (DIA, нужны ли центровочные кольца), вылет (ET,
  нужны ли проставки), диаметр; у шин — разница внешнего диаметра в %, ошибка спидометра при 100 км/ч, клиренс;
- показывает итог крупно: «Подходят ✓», «Подойдут с проставками / кольцами», «Не хватает данных», «Подойдут, но
  проверьте», «Не подходят» — и причины по пунктам;
- калькулятор «Сравнить размеры» (две шины, норма ±3 %) — тоже на телефоне.

**От сервера нужно одно — справочник посадки машин**: по марке, модели и году — штатные PCD, DIA, пределы ET, диаметры
дисков и размеры шин. Без него всё работает: человек вводит параметры своей машины сам (подсказка: «размер шин — на
наклейке в проёме двери водителя или в инструкции; PCD, ET и DIA — на внутренней стороне штатного диска»), они
запоминаются на телефоне. Справочник просто избавляет от ввода.

Рубильники приложения: `Config.автоПодбор` (кнопка «Подойдут ли?», `TryOnHub.swift`) и `Config.справочникАвтоподбора`
(спрашивать ли этот справочник, `AutoFitCar.swift`). Оба включены. Пока адреса нет (404) — приложение один раз получит
отказ, до перезапуска больше не спрашивает и сразу предлагает ввести параметры вручную.

Денег здесь нет: справочник бесплатный, в приложении ничего не продаётся.

## 0. Общее

- Адрес — от корня, без локали: `https://kliko.kz/api/autofit.php?action=car&…`.
- Только **GET**, только чтение. **Без входа**: ни кук, ни `csrf` приложение не шлёт (запрос из `URLSession` без кук,
  `Accept: application/json`, без подставных `Origin`/`Referer`). Справочник общий — личных данных в запросе нет,
  только марка, модель и год.
- Ответ — `Content-Type: application/json; charset=utf-8`, код 200 (и когда машины нет — см. ниже).
- **«Не поддерживается»** (приложение больше не спрашивает до перезапуска и просит ввести вручную): HTTP 404, 405, 410,
  501, любой 3xx (перенаправление на HTML), не JSON, `{"ok":false,"error":"unsupported"}`.
- **Временный сбой** (человеку — «нет связи со справочником, введите сами или попробуйте позже»; при следующем выборе
  машины приложение спросит снова): обрыв, таймаут 15 с, HTTP 5xx, **HTTP 429**.
- `lang` — `ru` | `kk` | `en` | `ar` (язык приложения). Текстов в ответе приложение не показывает — параметр на будущее
  (например, для имени поколения).

## 1. `GET /api/autofit.php?action=car&make=Toyota&model=Camry&year=2018&lang=ru`

| Параметр | Обязателен | Что это |
|---|---|---|
| `make` | да | марка — **как в `/api/auto_models.php?brands=1`** (`brand`): «Toyota», «Mercedes-Benz», «Lada (ВАЗ)»… |
| `model` | да | модель — **как в `/api/auto_models.php?brand=…`** (`models[].name`): «Camry», «RAV4», «Granta»… |
| `year` | нет | год выпуска (четыре цифры). Человек мог выбрать «Не помню год» — тогда параметра нет |
| `lang` | нет | язык приложения |

Марку и модель человек выбирает из того же справочника, что у мастера авто подачи, но может и вписать свою («Другая
марка: «…»», «Другая модель: «…»»). Сравнивайте **без учёта регистра и пробелов по краям**; псевдонимы («ВАЗ» →
«Lada (ВАЗ)», «Mercedes» → «Mercedes-Benz», «Camry» ↔ «Camry 70») — на стороне сервера.

### Ответ — машина найдена

Числа ниже — для примера формата, не справочные.

```json
{
  "ok": true,
  "make": "Toyota",
  "model": "Camry",
  "year": 2018,
  "gen": "XV70",
  "pcd": "5x114.3",
  "dia": 60.1,
  "et_min": 35,
  "et_max": 45,
  "rim_sizes": [16, 17, 18],
  "tire_sizes": ["205/65 R16", "215/55 R17", "235/45 R18"],
  "rim_width_min": 6.5,
  "rim_width_max": 8,
  "bolt": "M12x1.5"
}
```

Поля можно положить и в объект `car` (`{"ok":true,"car":{…}}`) — приложение понимает оба вида.

| Поле | Тип | Обязательно | Что значит и как приложение его использует |
|---|---|---|---|
| `ok` | bool | да | `true` — машина найдена |
| `pcd` | string | желательно | разболтовка: «5x114.3», «4x100», «6x139.7». Можно и числом с `bolts`: `"pcd": 114.3, "bolts": 5` |
| `dia` | number | желательно | центральное отверстие ступицы, мм (60.1, 67.1, 54.1) |
| `et_min`, `et_max` | number | желательно | пределы штатного вылета, мм (могут быть отрицательными). Одно значение — `"et": 45` |
| `rim_sizes` | number[] | желательно | штатные посадочные диаметры, дюймы. Строки «R17» тоже понимаются |
| `tire_sizes` | string[] | желательно | штатные размеры шин «205/55 R16» — **первый главный** (с ним сравнивается по умолчанию) |
| `rim_width_min`, `rim_width_max` | number | нет | пределы ширины обода, J — если знаете; иначе ширину не проверяем |
| `bolt` | string | нет | крепёж («M12x1.5», «M14x1.5») — только показываем |
| `make`, `model`, `year`, `gen` | — | нет | эхо и имя поколения — для отладки, приложение их не читает |

Проверки на телефоне (чтобы было понятно, зачем каждое поле):

- **PCD** — число болтов и окружность должны совпасть (допуск 0,35 мм на запись «120.65 / 120.7»); у
  мультиразболтовки диска — хоть одна. Иначе «Не подходят».
- **DIA** — диск = ступица (±0,15 мм) — подходит; у диска больше — «нужны центровочные кольца диск×ступица» (67.1×60.1); меньше — «не
  сядет».
- **ET** — в `[et_min, et_max]` или ±5 мм — подходит; больше (колесо глубже) до 25 мм — «нужны проставки ≈N мм»,
  дальше — «упрётся в подвеску»; меньше (колесо наружу) до 15 мм — «проверьте арку», дальше — «не подходят».
- **Диаметр** — в пределах `rim_sizes` — подходит; больше/меньше — «проверьте». Нет `rim_sizes` — берутся посадки из
  `tire_sizes`.
- **Шины** — сравнение с тем из `tire_sizes`, у которого тот же посадочный диаметр (или ближайший по внешнему
  диаметру): разница внешнего диаметра до ±3 % — подходит, больше — предупреждение; спидометр при 100 км/ч; клиренс.

Пустые или странные значения приложение отбрасывает (PCD — 3–10 болтов и 90–210 мм; DIA — 50–175 мм; ET — от −65 до
80 мм; диаметры — 12–26″; ширина — 3,5–13J). Если после этого не осталось ничего — считается «машины нет».

### Ответ — машины нет или год нужен

```json
{"ok": false, "error": "not_found"}
```

```json
{"ok": false, "error": "ambiguous"}
```

`ambiguous` — года нет, а у поколений модели разные PCD или DIA (бывает, что новое поколение получило другую
разболтовку или ступицу).
Лучше честно ответить `ambiguous`, чем отдать неверные числа. Если у всех поколений параметры одинаковые — отвечайте
и без года.

Приложению оба ответа значат одно: «в справочнике пока нет параметров этой машины — введите их сами, это минута».
Ответ «нет» для этой марки, модели и года приложение помнит до перезапуска (повторно не спрашивает).

## 2. Откуда взять данные

Два пути, можно совмещать.

**А. Купить.** Готовые справочники посадки по марке, модели и году: например, **Wheel-Size API** (wheel-size.com —
болтовой рисунок, центральное отверстие, штатные и допустимые размеры дисков и шин, вылеты по поколениям и рынкам), или
аналоги у поставщиков шинных каталогов. Перед покупкой проверьте лицензию: можно ли **кэшировать** ответы у себя и
отдавать их своим пользователям через свой API (обычно — да, по тарифу). Ключ API — **только на сервере**, в
приложение он не попадает. Для Казахстана берите рынок СНГ/«Россия»/«Ближний Восток» — у машин серого ввоза (ОАЭ, США,
Корея) бывают другие диски.

**Б. Собрать.** Своя таблица, заполняется вручную и по открытым данным (инструкции производителей, наклейки, каталоги
шинных центров-партнёров). Начать с самых частых моделей в объявлениях авто на Kliko (Toyota Camry, Corolla, RAV4, Land
Cruiser Prado, Lexus RX, Hyundai Accent/Elantra/Tucson/Sonata, Kia Rio/K5/Sportage, Chevrolet Cobalt/Nexia/Onix,
Lada Granta/Vesta/Niva, Volkswagen Polo, Skoda Rapid, Nissan X-Trail, Mitsubishi Outlander…) — это закроет большую
часть запросов. Что не нашлось — человек введёт сам; можно **логировать без данных человека**, каких марок и моделей не
хватило (только `make`, `model`, `year`, счётчик), чтобы знать, что добавлять.

Схема таблицы (пример, MySQL):

```sql
CREATE TABLE autofit_cars (
  id            INT AUTO_INCREMENT PRIMARY KEY,
  make          VARCHAR(64)  NOT NULL,          -- как brand в auto_models.php
  model         VARCHAR(96)  NOT NULL,          -- как models[].name
  gen           VARCHAR(64)  NULL,              -- «XV70»
  year_from     SMALLINT     NOT NULL,
  year_to       SMALLINT     NULL,              -- NULL — выпускается
  pcd_bolts     TINYINT      NULL,              -- 5
  pcd_mm        DECIMAL(5,2) NULL,              -- 114.30
  dia_mm        DECIMAL(5,2) NULL,              -- 60.10
  et_min        SMALLINT     NULL,
  et_max        SMALLINT     NULL,
  rim_sizes     JSON         NULL,              -- [16,17,18]
  tire_sizes    JSON         NULL,              -- ["205/65 R16","215/55 R17"]
  rim_width_min DECIMAL(3,1) NULL,
  rim_width_max DECIMAL(3,1) NULL,
  bolt          VARCHAR(24)  NULL,              -- «M12x1.5»
  source        VARCHAR(32)  NOT NULL,          -- «wheel-size», «manual»
  updated_at    TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY k_car (make, model, year_from)
);
CREATE TABLE autofit_alias (alias VARCHAR(96) PRIMARY KEY, make VARCHAR(64) NOT NULL, model VARCHAR(96) NULL);
```

Поиск: `make`, `model` (через `autofit_alias`, без регистра) и `year BETWEEN year_from AND COALESCE(year_to, 9999)`.
Нет года — все поколения модели; если PCD и DIA у них совпадают — объединить (`rim_sizes`, `tire_sizes` — объединение,
`et_min` — наименьший, `et_max` — наибольший), иначе `ambiguous`.

## 3. Кэш

- **На сервере**: ответы купленного API — в свою таблицу (или кэш) на срок, который разрешает лицензия (например, 90
  дней); повторно наружу не ходить.
- **HTTP**: `Cache-Control: public, max-age=86400` на удачные ответы и `max-age=3600` на `not_found` — справочник не
  меняется часто, CDN/прокси могут отдавать его сами. Приложение своё хранение ведёт само (ниже), на HTTP-кэш не
  полагается.
- **В приложении**: найденные параметры — на телефоне 30 дней (до 30 машин, `UserDefaults`, ключ `kliko.autofit.cars`);
  выбранная машина и её параметры (из справочника или введённые) — пока человек не нажмёт «Забыть мою машину»
  (`kliko.autofit.garage`). «Нет такой машины» — до перезапуска приложения.
- Ограничение частоты — по IP (например, 60 запросов в минуту) ответом **429**: приложение поймёт его как «нет связи»
  и не запомнит машину как отсутствующую.

## 4. Проверка

```bash
curl -sS -H 'Accept: application/json' 'https://kliko.kz/api/autofit.php?action=car&make=Toyota&model=Camry&year=2018&lang=ru'
curl -sS -H 'Accept: application/json' 'https://kliko.kz/api/autofit.php?action=car&make=Nope&model=Nope&lang=ru'   # not_found
```

Пробу можно добавить в «Новые адреса сервера» в `.github/workflows/ios-check.yml` (job `api-probe`) рядом с пробами
`tryon.php`.

## 5. Что ещё поможет (по желанию)

- **Характеристики объявлений.** Точность сверки зависит от того, что продавец указал. Форма подачи сайта уже просит у
  шин «Ширина», «Профиль», «Диаметр», «Сезон», у дисков — «Диаметр», «Ширина (J)», «Разболтовка (PCD)», «Вылет (ET)»,
  «Ступица (DIA)» (`E_SPECS` → `tire`, `wheel`) и «Подходит к марке / Модель / Годы» — хорошо бы, чтобы они **всегда**
  приходили в `specs` объявления (`/api/listings.php?id=`) с этими же `label`, а PCD, ET и DIA у дисков были
  обязательными. Приложение понимает и `label` на казахском и английском (по корням слов), но русские — надёжнее.
- **«Колёса в сборе».** Если на сайте появится отдельный признак (`wheel_kit: true` или подраздел), приложение сможет
  не угадывать по словам «в сборе», «на дисках».
