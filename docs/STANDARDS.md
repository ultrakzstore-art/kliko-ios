## 1. Суть

**Стандарт — общий язык продавца, покупателя и цены.** На коробке, наклейке и в паспорте вещи стандарт уже написан:
«E27», «PC4-3200AA-SA2», «VESA 300×300», «205/55 R16», «R44/04 9–18 kg». Kliko читает его, а не заставляет заполнять
анкету, и дальше всё работает от него.

| Кто | Что даёт стандарт |
|---|---|
| Продавец | Ставит касанием: из названия, шаблоном или камерой по маркировке. Сразу видит «Что почём по вашему стандарту». Объявление попадает в «Подходит моему» и «Для вас» |
| Покупатель | «Подходит вашему ноутбуку ✓», «Нужна деталь: переходник E14→E27», «Не подходит: DIMM в ноутбук не встанет». Фильтр «Для моего». Подсказки «можно так или так» с ценами |
| Цена | Считается по стандарту, а не по разделу: «DDR4 SO-DIMM 16 ГБ, б/у, Алматы: обычно 10–12,5 тыс ₸ за модуль · 11 продавцов · 90 дней» |
| «Моё» | Каждая вещь — набор стандартов. Отсюда подходящие новинки, апгрейд, «Куплено на Kliko 12.10 · 25 000 ₸», «Продать своё» с готовыми параметрами и ценой |

Пять решений, которые держат всё в одном ключе:

1. **Не второй каталог.** Реестр — общий словарь поверх живого: габариты (`КаталогРазмеров`, `rules.dims`: 44 вида,
   176 образцов), размеры одежды и обуви (`ТаблицыРазмеровОдежды`, `rules.sizes`: 13 таблиц), шины и диски
   (`СтандартыКолёс`, `AutoFitMath`, `parts`), телефоны (`MyThingsPhones`, 69 моделей), электроника
   (`ХарактеристикиЭлектроники`, `E_SPECS`), мерки (`ТиповыеМеркиМоего`). Они входят ссылкой. Новые семьи (дом, ПК,
   зарядки, дети, хобби, инструменты, стройка) живут в каталоге.
2. **Два ключа у семьи.** `std` — подходит ли к моему; `pkey` — что почём. Видеокарта: совместимость по длине, питанию и
   PCIe, цена — по чипу. Размер одежды: совместимость есть, ключа цены нет (цену задаёт бренд).
3. **Пять уровней** — те же, что у «Подойдут ли?» (`УровеньАвтоподбора`): «Подходит» · «Нужна деталь» (деталь
   названа) · «Неизвестно» (не хватает данных в «Моём» — один вопрос) · «Проверьте» · «Не подходит». Из текста продавца
   — никогда не выше «Проверьте».
4. **Чип — это заявление продавца.** Выбрал «160×200» или «E27» — значение его (`std_src: ""`), уровень может быть
   «Подходит». «Примерно» — только у выведенного (рама по росту, «обычно 300×300 у 55″»).
5. **«Моё» — на телефоне.** Сервер видит только значения стандартов в теле POST («цоколь E14»), без человека, и то, что
   и так есть в сделке. В аккаунте хранится только то, что человек явно включил сам: push «Новинок» по вещи (§6.4) —
   как сохранённый поиск. Вещи «Моих детей», вес и рост в сеть не уходят никогда.

## 2. Модель данных

### 2.1. Семья стандарта

| Поле | Пример | Что |
|---|---|---|
| `key` | `ram_module` | латиница, навсегда |
| `group` | `pc` | одна из 18 групп; группа ведёт в раздел «Моего» |
| `title` | «Оперативная память» · «Жедел жады» · «Memory module» · «الذاكرة العشوائية (RAM)» | ru, kk, en, ar |
| `src` | «JEDEC» | документ-источник; `market: true` — ряд рынка, а не норма |
| `ref` | `E_SPECS ram.type/capacity/mhz` | какой живой каталог семья представляет |
| `fields`, `main` | `gen`, `form`, `mts`, `gb`, `kind`; главные — `gen`, `form`, `gb` | без главных — «Проверьте» у объявления, «Неизвестно» в «Моём» |
| `match`, `need` | `fn: ram_fit`; потребность `gen`, `form`, `kind`, `max_gb` | правило сверки и что «нужно моему» |
| `cats`, `keywords` | `ram`, `laptops`; «оператив», «озу», «ddr4», «жедел жады» | где спрашивать и как узнать вид товара (как `КаталогРазмеров.вид`) |
| `why`, `presets`, `title_examples`, `where`, `ocr` | «Ноутбук · 16 ГБ DDR4 3200»; наклейка «PC4-3200AA-SA2» | как заполнить без мучений |
| `line` | «ОЗУ {gen} {form} {gb} ГБ {mts}» | кусок строки «Параметры: …» до `store` |
| `price` | `ram:{gen}-{form}:{gb}`, за модуль, срезы `cond`, частота | ключ цены |
| `fit_std` | `true` / `false` / `"kids_optin"` | можно ли слать значение «Моего» серверу |

### 2.2. Значение у объявления и в «Моём» — одна грамматика

```json
"std": { "ram_module": { "gen": "DDR4", "form": "SO-DIMM", "gb": 8, "mts": 3200 } },
"std_src": "scan", "qty": 2
```

- `std` — `{семья: {поле: значение}}`; краткая форма `{"lamp_base": "E14"}` = первое главное поле. Числа — с точкой,
  строки — каноном каталога (`5x114.3`, `160x200`, `SO-DIMM`), диапазоны `[от, до]`, списки массивом.
- `qty` — сколько единиц: комплект шин 4, кит ОЗУ 2, упаковка ламп 10. Без него цена за штуку врёт.
- `std_src` — откуда: `""` (продавец, в том числе выбранный чип), `title` (из названия, подтверждено), `scan`
  (камера, подтверждено), `ai` (Kliko AI, подтверждено), `model` (по модели из справочника), `tpl` (выведено
  примерно — не выше «Проверьте»), `text` (сервер разобрал старый текст — не выше «Проверьте»), `deal` (только в «Моём»:
  снимок купленного).
- Уже существующие поля — **ссылки, а не копии**: шины и диски — `parts` (std вычисляется при выдаче), одежда —
  `storage` / `size_sys` / `size_all`, габариты — `dim_*`, чехлы — `device_models`, сумки — `fits_diag_max`,
  электроника — слоты `E_SPECS` по таблице `e_specs_map`. Касание образца кровати ставит и `dim_*`, и
  `std.bed_size` — один выбор, два слоя: у габаритов остаётся `dims_src: "tpl"` («примерно» — про высоту и раму,
  `SERVER_DIMENSIONS.md` §1.2), у `std` — заявление продавца (`std_src: ""`): спальное место 160×200 он выбрал сам.
- В «Моём» значения хранятся каноном, а не номером ряда (как размеры: «хранится значением своей системы») — ряды
  меняются, профиль не ломается.

### 2.3. Типы значений

| Тип | Пример | |
|---|---|---|
| `enum` | E27, AM5, DOT 4, H7 | закрытый ряд; вне ряда — «Другое» до 40 знаков, у покупателя «Проверьте» |
| `num` + единица | 550 Вт, LI 91 = 615 кг, 806 лм | канонические единицы: мм, см, дюймы, Вт, В, А, кг, ГБ, МТ/с, лм, К |
| `range` | кресло 9–18 кг, кронштейн 32–70″ | `[от, до]` |
| `dims`, `pattern` | 160x200; 205/55R16; 5x114.3 | латинская `x`, точка |
| `set` | шаблоны VESA кронштейна, коды картриджа, модели телефонов | до 20 значений |
| `compound` | планка: gen + form + МТ/с + ГБ + UDIMM/RDIMM; аккумулятор: А·ч + CCA + полярность + клеммы + корпус | несколько полей |
| `table` | ссылка на `rules.sizes` | размеры одежды и обуви |
| `id` | OEM-номер, GTIN/EAN-13, ISBN | самый точный «что почём» |

### 2.4. Нормализация и синонимы — одна функция у сайта и приложения

Строчные, «ё» = «е» → кириллица-двойник → латиница (Е27 → E27, ЕТ45 → ET45, АМ4 → AM4; у шин «Р16» → R16) → «х»,
«×», «*» между цифрами → x, запятая → точка (5х114,3 → 5x114.3) → единицы (гб → GB, вт → W) → синонимы → канон.
Распознавание камерой: рядом с цифрами O → 0, I → 1, S → 5 — только если иначе значение вне ряда; итог притягивается к
ближайшему значению ряда (шаблоны VESA, PCD, ступени ватт): **стандарты дискретны, поэтому неточный замер даёт точный
ответ**. Серийные номера, IMEI, S/N отбрасываются.

Синонимы рынка КЗ и СНГ (каталог, `aliases_market`, 100 записей): полуторка → 140×200, крона → 9V, пальчиковая → AA,
липучка → фрикционные, шиповка → шипованные, 880 → H27/1, T10 → W5W, 1156 → P21W, PC4-25600 → DDR4-3200, ПСБ-С 25 →
ППС-25, A-III → A400, М500 ≈ ЦЕМ 42,5, 700C и 29er → BSD 622, MR16 → GU5.3 (12 В), «таблетка» — GX53 в лампах и
CR2032 в батарейках. **Казахский пласт** (42 записи): жедел жады → ОЗУ, ноутбукқа арналған → SO-DIMM, бейнекарта, қуат
блогы, аналық плата, шам, жылы / суық жарық → 3000 / 6500 K, бір жарым кісілік → 140×200, қысқы / шипті / шипсіз /
жазғы → сезон шин, зарядтағыш, балалар автоорындығы, мотор майы, аккумуляторсыз → «без АКБ». Неоднозначное
(«двуспальная», «екі кісілік» — 140, 160 или 180) значение не ставит, а предлагает чипы.

**Эталоны** — раздел `tests` каталога: 30 примеров нормализации, 20 строк маркировки, 16 названий, 43 пары для
сверки, 9 случаев цены. Не двойники латиницы («ддр4», «содимм») — синонимами семьи, не транслитом. Их прогоняют
и PHP сайта, и тесты приложения; расхождение — ошибка.

### 2.5. Сверка

| Правило | Что | Примеры |
|---|---|---|
| `eq` | равно после нормализации | цоколь, тип и форма ОЗУ, сокет, байонет, BSD велоколеса |
| `eq_tol` | равно с допуском | PCD ±0,35 мм, DIA ±0,15, кровать и матрас ±1 см, диагональ ±0,35″, Mondopoint ±0,5 |
| `in_set` | входит в список | мультиразболтовка, модель телефона в `device_models`, код в списке картриджа, шаблон ТВ в шаблонах кронштейна |
| `range` | моё внутри диапазона объявления | класс кресла, обхват ошейника, ET-окно |
| `gte` | объявление не меньше нужного | БП, индекс нагрузки, IP ванной, мощность зарядки |
| `lte` | не больше предела | длина видеокарты ≤ корпус − 10 мм, плата ≤ корпуса, шкаф ≤ потолок − 10 см |
| `backward` | новее в старом работает на скорости старого | PCIe 4.0 SSD в слоте 3.0, частота ОЗУ, HDMI |
| `adapt` | подойдёт с названной деталью | кольца, проставки, E14→E27, EF-EOS R, FTZ, пластина VESA, рамка 2DIN→1DIN, 2×8-pin→12V-2x6 |
| `graph` | таблица связей | сокет ↔ чипсет ↔ DDR; NNN ↔ Prolink; FLEXVOLT → 18V XR; PS4 → PS5 |
| `fn` | общая функция | шины ±3 % внешнего диаметра, диски — `AutoFitMath`, `ram_fit`, `m2_fit`, `gpu_fit`, `psu_need`, `vesa_fit` |
| `geom` | пройдёт ли в дверь и лифт | два меньших габарита против прохода в свету, запас 2 см; только наклоном — «Проверьте» |

Итог по вещи — **худший пункт**, с причинами в цифрах: «Длина 240 мм, корпус до 320 ✓», «БП 500 Вт — NVIDIA советует
550 ⚠». Сервер отдаёт `ok`, `adapt`, `check` (прежние `rings`, `spacers` → «Нужна деталь»; `text` → «Проверьте»);
«Неизвестно» — только на телефоне.

### 2.7. Версия

`v` вида `2026-10-16-1`, ETag; встроенная копия в приложении, серверная главнее по `v`. Семьи и значения только
добавляются; старое имя навсегда синоним; ключ семьи не переименовывается. Незнакомое у объявления — строка
характеристики без сверки; незнакомое в «Моём» — пропускается при чтении (как сейчас `ЗаписьМоего`).

### 2.8. Вещь «Моего» — цифровой двойник

```
ВещьМоего { id, family, category, title, std, qty, src: deal | scan | title | model | '',
            parent: {car | computer | room | me | kid | pet | device, id},
            bought: {at, price, via: kliko_deal | elsewhere | receipt, deal_id?, listing_id?, city?, cond},
            warranty_till, state: in_use | stored | for_sale | sold | gone,
            history: [{at, ev: bought | installed | moved | listed | sold | removed}], watch, listing_id }
```

Живёт в `ЗаписьМоего` v2 (новый массив `items`, короткие ASCII-ключи, терпимое чтение), до 300 вещей и 50 событий на
вещь: обычно файл «Моего» — десятки КБ, в пределе ≈ 1 МБ; читается и пишется вне главной нити, хаб берёт сводку (имя,
семья, место), а не всю историю. Нынешние машины, телефон и устройства не переносятся:
вещи вешаются на них через `parent`. «Удалить всё «Моё»» стирает и вещи, и историю.

## 5. Продавец: стандарт ставится сам, человек подтверждает

На шаге «Характеристики» — блок **«Параметры — по желанию»** рядом с «Размеры — по желанию», тот же облик. Ни «Далее»,
ни «Опубликовать» он не держит. Семьи — по разделу (`cats`) и словам названия, тем же правилом, что вид товара у
`КаталогРазмеров`; обычно одна–три. Под заголовком одна строка `why`: «Покупатели с подходящим ноутбуком или ПК увидят
«Подходит» и найдут планку в «Для вас»». Видны только главные поля, остальное — под «Ещё».

Пять способов — от нуля касаний к ручному вводу:

| # | Способ | Как | `std_src` |
|---|---|---|---|
| 1 | **Из названия** | разбор синонимами на телефоне: «Kingston 16GB DDR4 3200 SODIMM» → DDR4 SO-DIMM 16 ГБ 3200; «Ryzen 5 5600» → AM4; «B550M DS3H» → AM4, B550, Micro-ATX; «Лампа Е27 9Вт тёплая» → E27; «Кронштейн VESA 400x400 до 50 кг» → 400×400, 50 кг; «Зарядка 65W GaN PD» → USB-C PD 65 Вт. Чипы «Нашли в названии — верно?», одно касание. У M.2 без длины — 2280 с пометкой «проверьте». Неоднозначное («двуспальная») — вопрос чипами | `title` |
| 2 | **Шаблоны** | чипы, частые первыми: «Ноутбук · 16 ГБ DDR4 3200», «ПК · 32 ГБ (2×16) DDR5 6000», «E27 · груша», «GX53 · таблетка», «VESA 300×300», «160×200 двуспальная», «I · 9–18 кг», «650 Вт · 80+ Gold · ATX 3.1», «USB-C PD 65 Вт». Касание ставит все поля. Образцы габаритов со стандартом (кровать, ТВ 55″, ноутбук 15,6″) ставят и `dim_*`, и `std`. Поле «Сколько штук»: 1 / 2 / 4 у шин, «2×8» у ОЗУ, упаковка у ламп | `""` |
| 3 | **Камерой — «Прочитать маркировку»** | один сканер вместо отдельных: обобщённый сканер колёс (`WheelScan`: VisionKit DataScanner или Vision, голоса нескольких кадров), с подсказкой по семье. Читает: наклейку планки «16GB 1Rx8 PC4-3200AA-SA2» → DDR4 SO-DIMM 3200; колбу «E27 230V 9W 806lm 4000K»; оранжевую этикетку кресла «R44/04 9–18 kg»; блок зарядки «20V⎓3.25A» → 65 Вт; БП «650W 80 PLUS Gold»; аккумулятор «75Ah 680A(EN)», «55B24L»; канистру «5W-30 API SP VW 504 00»; боковину шины и DOT «3519» (35-я неделя 2019 — возраст в цену); «57-622» велопокрышки; ободок объектива «Ø58»; «3/8 1.3 52E» цепи; штрихкод (GTIN, ISBN). VESA без наклейки — линейкой «Поместится ли?» (`FitBoxRuler`) или банковской картой рядом (ISO/IEC 7810: 85,60 × 53,98 мм), замер притягивается к ближайшему шаблону. Серийные номера и IMEI отбрасываются, кадры не сохраняются | `scan` |
| 4 | **Модель** | модель из каталога (`api/devices.php`) подставляет связанное: ноутбук → тип и форма ОЗУ, слоты M.2, мощность USB-C; телефон → разъём и мощность | `model` |
| 5 | **Руками** | только из ряда значений с поиском по синонимам; вне ряда — «Другое» до 40 знаков (у покупателя «Проверьте»), редкое — «Редкое значение — проверьте» | `""` |

Kliko AI (`recognize`, `accept_draft`) может предложить `std` — только «проверьте», введённое человеком не трогает.

**Что продавец получает сразу** — выгода без обмана: как только заполнены главные поля, — карточка «Что почём по вашему
стандарту» (§7) и превью карточки с меткой «Параметры: DDR4 · SO-DIMM · 3200»; «Подходит моему» у покупателя станет
«Подходит», а не «Проверьте по описанию». Честное «вас найдут» — только то, что сервер знает: сохранённые поиски с этим
стандартом и просмотры раздела за 7 дней. Сколько людей с подходящим «Моим» — мы не знаем (оно у них на телефонах), и так
и пишем. Никаких напоминаний «заполните стандарты».

**Пока сервер не хранит `std`** (нет `rules.std.store`) — последней строкой описания «Параметры: ОЗУ DDR4 SO-DIMM 8 ГБ
3200 · 2 шт» (как «Размер: …»): вынимается и ставится заново при правке, в минимум описания не идёт (договор §3.6).

**«Продать своё»** из «Моего» открывает подачу на шаге «Фото»: раздел, название по шаблону («Оперативная память DDR4
SO-DIMM 8 ГБ 3200»), `std`, `qty`, состояние «б/у», чипы описания («Куплено на Kliko в 10.2026», «Работает без
нареканий»). Фото — только новые по плану кадров: снимки прежнего продавца — его фото и прежнее состояние. Цена — чипы
«Быстро» (P25) · «Как у всех» (середина) · «Своя» — только при ≥ 8 продавцах по стандарту; при 3–7 — строка «N
продавцов: от X до Y» и «Своя»; меньше — «Своя» и «Таких пока мало». Ничего не выбрано заранее. Флажок «Показать
«Куплено на Kliko»» — по желанию, без цены. «Одно касание» = открыть готовую подачу, а не опубликовать: фото и
«Опубликовать» — за человеком.

## 6. Покупатель

### 6.1. Окно объявления

- Чипы стандарта под ценой: «DDR4 · SO-DIMM · 16 ГБ · 3200 · 2 шт»; у пунктов характеристик — значок и подпись на языке
  экрана.
- **«Подходит моему»** (нынешняя `ПлашкаПодходитМоему`) — по любой семье, с пунктами и причинами:
  - «Ноутбук Lenovo: DDR4 ✓ SO-DIMM ✓ свободный слот ✓ → станет 16 ГБ»;
  - «В ваш ПК: DDR4 DIMM ✓, но у вас ноутбук — нужна SO-DIMM ✗»;
  - «Люстра в гостиной: 5 × E14 — нужна деталь: переходник E14→E27»;
  - «Кронштейн: VESA 300×300 ✓, до 40 кг ✓ (ваш ТВ 23 кг)»;
  - «Работает медленнее: PCIe 4.0 в слоте 3.0»;
  - «Пройдёт в вашу дверь 80 см? Наклоном — проверьте»;
  - не хватает данных — **один вопрос**: «Сколько слотов памяти? Снимите Диспетчер задач».
  Внизу мелко: «Проверили по стандарту, а не по экземпляру»; значение из текста — «По описанию продавца — уточните».
- Строка **«Что почём»** (§7) — в «Разборе объявления».
- Ссылка «Ещё по этому стандарту» — лента с `std=` и сортировкой по цене.
- **«Проверить при получении»** — в безопасной сделке перед «Подтвердить получение»: снять маркировку тем же сканером →
  «Совпадает со стандартом объявления ✓» или спор с причиной «Не соответствует указанному стандарту». Не только
  доказательство в споре, а способ его не допустить.

### 6.2. Лента, фильтры, поиск

- В листе «Фильтры» раздела — чипы **«По стандарту»** с числами: «Цоколь: E27 · E14 · GU10 · GX53», «Память: DDR4 ·
  DDR5 · SO-DIMM», «Разболтовка: 4x100 · 5x114.3». Обычный фильтр, личных данных нет: `std=` в адресе.
- Чип **«Для моего ▾»** — выбор, для чего: «Моя Camry · Мой ноутбук · Спальня · Гостиная · Барсик». Значения — в теле
  POST (`fit_std`), как `fit_*`. Карточки: «Подходит ✓», «Нужна деталь: кольца», «Проверьте»; «Не подходит» не
  показывается. Конец честный: «Вы посмотрели все 37 подходящих». Пока сервер не включил `fit_std`, приложение отбирает
  загруженную страницу само с полосой «Уточнено по загруженным», как сейчас.
- **Поиск**: «205/55 R16», «E27», «DDR4 16» узнаются как стандарт → чип-фильтр и подсказка «По стандарту: 23 · по тексту:
  61».

### 6.3. «Для вас» на главной

- Собирается на телефоне: **один** POST ленты (`sort=new`) с `fit_std` и `fit_*` по всем заполненным вещам — группами
  через `|`; ответ `fit_match.std.g` говорит, для какой вещи.
- Полка на вещь, не больше 6 полок и 12 карточек в полке, по кругу не больше 3 на вещь; только «Подходит» и «Нужна
  деталь»; своё объявление не показывается, свой город первым. У каждой карточки причина: «Для вашей Camry · 5×114.3»,
  «Ваш ТВ · VESA 300×300»; «Почему я это вижу?» — та же причина.
- Связки по стандарту, а не «покупают также» (граф `pairs`): ТВ → кронштейны; кровать → матрас → простыня на резинке →
  пододеяльник под моё одеяло; камера RF → объективы RF и EF через переходник, аккумулятор; PS5 → SSD PCIe 4.0;
  велосипед 622 → покрышки; принтер → картриджи моего кода; ноутбук USB-C PD 65 Вт → зарядки ≥ 65 Вт.
- Сезон только меняет порядок полок (1 октября – 30 ноября — зимние шины выше, 15 марта – 15 мая — летние), без
  отдельных запросов и уведомлений.
- ТОП-вставки (`slot: "top"`) в полку не берутся: в «Для вас» и «Новинках» — только обычная выдача по новизне;
  ТОП-объявление попадает туда на общих основаниях, со своей пометкой, без подъёма. Так данные «Моего» не выбирают
  рекламу. Пустое «Моё» — полки нет и напоминаний нет. «Скрыть подборку» — одним касанием.
- Скорость: полка грузится **после** основных рядов главной (`home=1`), лениво, кэш 30 минут; на запуске новых запросов
  нет; каталог — статический снимок, разбор JSON не на главной нити.

### 6.4. «Новинки для моего»

- У вещи переключатель «Сообщать о новом подходящем» — по умолчанию выключен; предлагается один раз в момент пользы
  («Сообщать о новых шинах 205/55 R16 для Camry?»); общий выключатель — Кабинет → «Новинки для моего».
- Ещё одно дело того же фонового задания `kz.kliko.app.saved-search` (`ПроверкаПоисков`, вместе со сниженными ценами):
  POST с `fit_std` и `sort=new`, до 200 запомненных номеров на вещь, только «Подходит» и «Нужна деталь».
- **Не больше одного локального уведомления в день** на всё «Моё», одним сообщением: «Для вашей Camry 3 новых: зимние
  205/55 R16 от 160 000 ₸ за 4 шт»; тишина 22:00–09:00.
- «Следить за ценой стандарта» (из подсказок апгрейда): уведомить, когда «от» по ключу цены упало на 10 % и больше.
- Push сервера — позже и по отдельному согласию (договор §7.2): сохранённый поиск со стандартом в аккаунте. Подпись
  подписки — только стандарт («Лампы E14», «Шины 205/55 R16»), без имён вещей «Моего» («гостиная», «Camry», прозвище):
  связь подписки с вещью — только на телефоне. Вещи «Моих детей» в подписки не попадают.

### 6.5. Подсказки «можно так или так»

Экран «Можно улучшить» у вещи (кнопка «Как улучшить?» на карточке компьютера, строка «Для вас», вопрос на странице
детали). Цель — чипами: Игры · Учёба и работа · Монтаж и фото · Больше места · Быстрее включается. Бюджет — чипами.

1. **Диагноз только по фактам**: «8 ГБ — тесно для Windows 11 с браузером», «система на жёстком диске — главный тормоз»,
   «память распаяна — добавить нельзя».
2. **2–3 варианта**: A — меньше всего денег, заметная польза; B — сбалансированно; C — по-крупному или «продать свой и
   взять другой». Последней строкой всегда **«Можно ничего не менять»**.
3. **Каждый вариант** — проверки ✓ / ⚠ / ✕ построчно правилами семей; «от X ₸» — самое дешёвое живое объявление по
   стандарту в городе (нажимается); «обычно Y–Z ₸ · n продавцов · 30 дней» — если есть; «Смотреть n предложений»;
   «Поставить: сами за 10 минут / услуга «Апгрейд ПК»» (раздел `pc-upgrade`).
4. Вариант с «Не подходит» в карточки не попадает — свёрнутой строкой «так нельзя: SO-DIMM в ПК не встанет». Никаких
   FPS, процентов и «в 2 раза быстрее»: мы их не измеряли. Чего проверить нельзя — прямо: «BIOS — уточните у продавца
   платы».

Примеры:

| Вещь | Так | Или так | Или по-крупному |
|---|---|---|---|
| Ноутбук, 8 ГБ DDR4 SO-DIMM 3200, слотов 1 из 2, SSD 256 ГБ M.2 2280 | +8 ГБ DDR4 SO-DIMM 3200 — станет 16 ГБ, двухканал · ✓ тип ✓ форма ✓ свободный слот · от 9 000 ₸ · 7 предложений | SSD 1 ТБ NVMe 2280 PCIe 3.0 вместо 256 ГБ · ✓ слот ⚠ перенос системы: корпус M.2 → USB-C или услуга · от 22 000 ₸ | A + B · от 31 000 ₸ |
| ПК: Ryzen 5 3600 (AM4), B450, GTX 1060, БП 500 Вт Bronze, корпус до 320 мм | RTX 4060 · ✓ длина ≈ 240 из 310 ✓ 8-pin ⚠ NVIDIA советует 550 Вт, у вас 500 ✓ PCIe 4.0 x8 на B450 — работает, теряет часть скорости · от … | RTX 4060 + БП 550–650 Вт Bronze · ✓ всё · от … + от 18 000 ₸ (по отдельным объявлениям) | Ryzen 7 5700X3D на ту же плату · ✓ AM4 ⚠ BIOS с поддержкой Ryzen 5000 · от … |
| MacBook Air M1, 8 ГБ | внешний SSD USB-C 1 ТБ · от … | продать свой (обычно X–Y ₸) → MacBook Air M2 16 ГБ от Z ₸ · доплата ≈ … | — |
| Camry, 205/55 R16 | зимние 205/55 R16 (штатный) — от 160 000 ₸ за 4 шт | 225/45 R17 — диаметр ±3 %, нужны диски R17 (сверка PCD/DIA/ET с машиной) | — |
| ТВ 55″, VESA 300×300, 18 кг | кронштейн фиксированный 300×300 — от … | наклонный или поворотный — от … | PS5 в 4K 120 Гц — нужен HDMI 2.1 у ТВ |

Правила компонентов (ОЗУ, SSD, видеокарта, БП, процессор, «продать и взять другое») — `upgrade` каталога. БП: нужно =
max(рекомендация производителя карты; (TDP процессора + TGP + 100 Вт) × 1,3) вверх до ряда 450 · 550 · 650 · 750 · 850 ·
1000 · 1200 · 1600 — это эвристика Kliko, а не стандарт, и так и подписано. «Продать и взять другое» — когда апгрейд
недоступен (распаяно) или сумма вариантов ≥ 60 % цены готового с нужным. В связке (карта + БП) — сумма «от» с подписью
«по отдельным объявлениям»; у компонента меньше 3 предложений — суммы нет.

## 7. «Что почём» по стандарту

**Срез**: ключ цены × состояние (новое / б/у; «на запчасти» — отдельно) × город → весь Казахстан × свежесть (окно семьи:
30 дней — видеокарты и телефоны, 90 — по умолчанию, 180 — объективы и редкое). Цепочка, как у `market_price`: стандарт →
модель → бренд → раздел, и в ответе `level` — подпись честная.

**Выборка**:

| Правило | |
|---|---|
| Один продавец — один голос | его медиана на срез; дубли (то же фото или текст) — одно предложение |
| Вне выборки | цена 0 и «договорная», аренда, услуги, опт и «лот», «на запчасти», объявления без `qty` у комплектных семей, не одобренные, своё |
| Единица | цена ÷ `qty`: шины и диски — **за комплект 4**, ОЗУ — за модуль, автолампы — пара, масло — литр, корм — кг, стройка — лист, м², м³, т |
| Выбросы | < 10 % и > 10× медианы — прочь; при ≥ 8 продавцах — Тьюки на логарифме; при < 8 — полоса [медиана ÷ 4; × 4] |
| Пороги | «от X ₸» — с 1 предложения (факт, ссылка на объявление; при ≥ 8 продавцах «от» ниже 0,4 × медианы пропускается — приманка); 3–7 продавцов — «5 продавцов: от X до Y» (по продавцам, а не по объявлениям); **≥ 8 продавцов — «обычно P25–P75» и середина**; < 3 — только список |
| «Продано через Kliko» | закрытые безопасные сделки (`outcome: sold`) — только при ≥ 5, медианой цены товара без доставки и комиссий, за единицу (÷ `qty` снимка), округлённо; одна сделка не раскрывается никогда |
| Тренд | факт, не прогноз: «за 90 дней середина ниже на 8 %» — только если в обоих окнах ≥ 8 продавцов; < 5 % — «без заметных изменений» |
| Округление | до 100 ₸ ниже 20 000; до 1 000 ₸ выше — без ложной точности |
| Защита от накрутки | только одобренные, один голос на продавца, минимум продавцов, заморозка резкого сдвига за сутки с пометкой «пересчитывается» (сдвиг, который держится 3 ночи подряд, принимается — рынок правда изменился); ТОП цену не двигает |
| Комплекты | шины и диски без `qty` в выборку не идут; перенос старых ставит `qty` из текста («комплект», «4 шт», «пара») — иначе цены шин пустые |

**Где показываем**:

| Где | Что |
|---|---|
| Окно объявления | строка под ценой → «Разбор объявления» (`ШкалаРынкаРазбора`): «DDR4 SO-DIMM 16 ГБ · б/у · Алматы · 90 дней: обычно 10–12,5 тыс ₸ за модуль · 11 продавцов · через Kliko продано 6, середина 10 500 ₸». Метки у цены — только `chip` сервера: «Ниже рынка на N %», «На уровне рынка». **«Дороже рынка» — никогда** |
| Подача | якоря «Срочно / Рынок / Высокая» из `market_price` с `level: std` — только при ≥ 8 продавцах (P25 / середина / P75); при 3–7 — одна строка «от X до Y» без достроенных якорей (нынешнее «× 0,85 / × 1,2 от середины» у `level: std` не применять); карточка «Что почём по вашему стандарту»: б/у и новые раздельно, свой город, шкала с нейтральной меткой своей цены (без красного и «дорого»); чипы «Как обычно: …» и — только при ≥ 5 продажах — «Как продавали через Kliko: середина …» (не «быстрее»: скорость продажи от цены мы не мерили); подставляется только касанием. В листе «Опубликовано» сравнения цен нет (`SERVER_SIZES.md` §5) |
| «Моё» | «Сколько стоит сейчас?» у вещи — по нажатию, б/у, свой город; кэш на день. Сводной «стоимости всего моего» по умолчанию нет |
| Апгрейд и «Для вас» | «от X ₸ · N предложений · город» |

**Честный текст** — всегда источник и окно: «по объявлениям Kliko за 90 дней · 11 продавцов · Алматы (цены продавцов, не
сделок)», «по всему Казахстану» при расширении, «Это цены объявлений, а не оценка вещи; состояние и комплект меняют
цену». Мало данных — «Таких пока мало — цену ставьте сами», без подстановки раздела под видом стандарта. Нельзя:
«выгодно», «лучшая цена», «цена упадёт», «успейте», «снизьте цену».

**Пока сервер не считает по стандарту** (`rules.std.price` нет) — телефон честно считает по найденному: лента раздела с
`std=` или запросом-синонимом → «по найденным 6 объявлениям: от 9 000 ₸», без «обычно». Так — для стандарта
**объявления** (он публичный). Запрос, собранный из **«Моего»** (подсказки апгрейда, «Сколько стоит сейчас?»), уходит
только телом POST (`std` и `q` в теле, договор §4.1), как `fit_*`; пока сервер их в теле не принимает — цены в
подсказках сами не подгружаются, а кнопка «Найти: DDR4 SO-DIMM 8 ГБ» открывает обычный поиск по нажатию, как если бы
человек набрал его сам. Конфигурация компьютера в адрес запроса не попадает.

## 8. «Моё»: цифровой двойник вещей

Всё на телефоне (Application Support/MyThings, вне резервной копии), «Удалить всё «Моё»» — одним шагом (хаб, «Данные на
телефоне» кабинета, выход из аккаунта). Каждый раздел заполняется за минуту: сначала самое полезное одним касанием,
остальное — когда понадобится. Кольца прогресса — как сейчас; ни серий, ни значков, ни напоминаний «заполните».

### 8.1. «Мой компьютер / ноутбук» — новый раздел, глубже всех

Главный путь — **снять телефоном экран компьютера** (распознавание на телефоне; серийные номера и имя компьютера
отбрасываются):

| Что снять | Что там написано | Что получаем |
|---|---|---|
| Windows: Ctrl+Shift+Esc → Производительность → Память | «Скорость: 3200 МГц», «Использовано гнезд: 1 из 2», «Форм-фактор: SODIMM», «16,0 ГБ» | ровно то, что нужно для «добавить планку» |
| Там же: ЦП, Диск 0, Графический процессор | модель процессора; «SSD (NVMe)» / «HDD»; видеокарта и «Выделенная память» | сокет, накопитель, видеокарта |
| Параметры → Система → О системе | процессор, установленная память | — |
| Меню Apple → Об этом Mac | чип M1…M4, память | «распаяно — улучшение только внешнее» |
| Наклейка на дне ноутбука | модель или MTM (Lenovo «82LN», HP «15s-fq5…») | модель → `api/devices.php laptops` |
| Блок зарядки | «Output 20V⎓3.25A» | 65 Вт USB-C PD |
| Надпись на плате, коробка | «B550M DS3H» | AM4, B550, Micro-ATX |
| Наклейки планок и БП | «PC4-3200AA-SA2», «650W 80 PLUS Gold» | ОЗУ, БП |

Ещё — по модели ноутбука или платы (когда сервер наполнит справочник) или чипами вручную.

Профиль: процессор и сокет; чипсет; ОЗУ (поколение, форма, частота, планки по слотам, всего слотов, максимум,
распаяно); видеокарта (чип, длина, разъёмы, TGP); БП (ватты, форма, 80 PLUS, разъёмы PCIe 6+2 и 12V-2x6); корпус
(форм-фактор, предел длины видеокарты и высоты кулера); накопители (слоты M.2: длина, NVMe / SATA, поколение PCIe;
отсек 2.5″); зарядка ноутбука; видеовыходы. У ноутбука на карточке — **«Что меняется / что распаяно»**. Неизвестное —
«не знаю», а не ноль. Кольцо полно, когда есть процессор, ОЗУ (тип, форма, слоты) и накопитель; БП и корпус — по
желанию. Отсюда — подсказки «можно так или так» (§6.5).

### 8.3. «Мои устройства» +

Зарядка и разъём каждого устройства (iPhone 15 и новее — USB-C, 12 и новее — MagSafe; «у вас 20 Вт USB-C — iPad Pro
зарядит медленно»), часы (группа ремешка, ширина ушек), консоль (платформа, накопитель), камера (байонет, объективы,
фильтры, аккумулятор, карта V30 для 4K), принтер (код картриджа — камерой со старого), наушники (разъём, кодек).

### 8.4. «Мои дети» — скрыт, пока родитель не включит

При включении — одна фраза: «Данные детей остаются на этом телефоне и никуда не отправляются». Прозвище (не имя), месяц
и год рождения, рост, вес, длина стопы, нынешнее кресло (камерой по оранжевой этикетке), машина с ISOFIX из гаража.
Фото, школы, адреса — не собираем. Из них на телефоне выводятся стандарты: кресло по группе или росту (и «скоро
вырастет», когда до границы < 10 %), размер по `kids_height` и `shoes_kids` (стопа + 0,5–1 см), кроватка, велосипед,
возраст игрушек, система бутылочек, подгузники по весу. Подбор — на загруженной ленте, на сервер ничего (решение
владельца — §13). Правило «ничего» — по месту вещи, а не по семье: вещь с `parent: kid` не уходит ни в `fit_std`, ни в
пакет цен, ни в подписки, даже если у семьи `fit_std: true` (мяч размера 3, LEGO Duplo, книга по ISBN выдают возраст
ребёнка). «Для вас» по детям — полкой из загруженной ленты.

Включение раздела меняет фразу `SERVER_MY_THINGS.md` §10.5 («детских размеров … в «Моё» нет») — в той же пачке
поправить её на «есть, только на телефоне, скрыто до включения, на сервер не уходит» и сверить App Review Notes
(раздел о «Моём»).

и стадии, ошейник и шлейка («Проверьте»), переноска, фильтр и нагреватель.

### 8.6. «Спорт и хобби», «Мои инструменты»

креплений); сноуборд (закладные, ширина); ракетка, блины; туристический газ; фотокамера. Инструменты: платформы АКБ
(«тушки» моей платформы — в «Для вас»), хвостовики, диаметр и обороты болгарки, цепь пилы, леска, шланги.

### 8.7. «Мой гараж» +

К колёсам — лампы по местам (ближний, дальний, ПТФ, поворот, габарит), аккумулятор (корпус, полярность, А·ч), щётки

### 8.8. Двойник: купленное — в «Моё», история, «Продать своё»

- **«Куплено на Kliko».** Безопасная сделка, где я покупатель, закрылась с итогом «продано» (`outcome: "sold"`; до него
  — статусы `released`, `confirmed`, `done`, `completed` в `ОбъявлениеПослеСделки`) → один вопрос после первой такой
  покупки: «Добавлять купленное на Kliko в «Моё»?» [Добавить] [Не сейчас] и переключатель «Добавлять само» (по
  умолчанию выключен). Вещь — из снимка сделки (`listing_snapshot.std`; без снимка — из `?id=`): «Куплено на Kliko
  12.10 · 25 000 ₸» (видит только владелец).
- **Куда положить**: ровно одно место с «Подходит» — кладётся само с «Отменить» (шины → на Camry, ОЗУ → в ноутбук,
  кровать → в спальню, чехол → на телефон); несколько — карточка «Куда положить?»; ни одного — «Вещи без места». ОЗУ,
  SSD, видеокарта — затем вопрос «Поставили?»: конфигурация (8 → 16 ГБ) меняется только после «Да». Одежда — через 3
  дня при открытии «Моего»: «Подошло? Да · Маломерит · Большемерит» → заметка бренда «Nike — беру EU 43», точнее
  «мой размер».
- Возврат (`outcome: "refunded"`) — вещь уходит сама.
- **История вещи**: куплено → поставлено → выставлено → продано. «Сколько стоит сейчас?» — по нажатию.
- **«Продать своё»** — §5. Через 30 дней после «Поставили новое» — тихая строка у старой вещи «Освободилась — продать?»
  (без уведомления). Сделка продажи закрылась — вещь сама в «Продано» (связь объявления с вещью — только на телефоне).
- **Покупки не на Kliko** (позже): QR фискального чека → открыть страницу оператора фискальных данных по касанию (запрос с
  телефона к ОФД, не к Kliko) → разбор позиций на телефоне → человек выбирает строку; или фото чека и коробки → разбор
  на телефоне. Не получилось — руками. Так «цифровизация реальности» покрывает не только купленное на Kliko.

## 9. Приватность и App Store

| Что | Как |
|---|---|
| Где живёт «Моё» | только на телефоне, вне резервной копии, без синхронизации; удаление одним шагом (5.1.1(v)) |
| Что уходит в сеть | только значения стандартов в теле POST ленты и цен («DDR4 SO-DIMM», «цоколь E14»), без привязки к человеку; не в журналы и аналитику сервера (`SERVER_MY_THINGS.md` §10). Тогда это не «сбор данных», анкета App Privacy не меняется. Если когда-нибудь придётся GET — сказать владельцу до включения |
| Тело, вес, рост | в `fit_std` не уходят (`fit_std: false`): матрас по весу, рама по росту, тренажёр, Mondopoint — на телефоне. Обхваты для одежды — только прежним `fit_me` (`SERVER_MY_THINGS.md` §3.6), рост и вес — никуда |
| Дети | раздел скрыт до включения; без фото и имён; в сеть ничего — по месту вещи (`parent: kid`), а не по семье (договор §10.4) |
| Подписка «Новинки» push-ом | единственное, что хранится в аккаунте, и только по явному нажатию: стандарт как сохранённый поиск, подпись без имён вещей. Это данные, связанные с человеком: до `rules.std.subs` сверить анкету App Privacy — сохранённые поиски там должны уже быть (если нет — добавить вместе) |
| Опись дома | на сервере её нет — это и защита от воров |
| Снимки экрана ПК и наклеек | распознавание на телефоне, кадры не сохраняются; серийные номера, IMEI, имя компьютера отбрасываются |
| Купленное | данные своей же сделки; в «Моё» — по согласию; метка «Куплено на Kliko» в новом объявлении — по выбору продавца, без цены, только месяц |
| Уведомления | локальные, по согласию, ≤ 1 в день, тишина 22:00–09:00; push сервера — только по отдельному явному включению (4.5.4: push не для рекламы без согласия) |
| Рекомендации | «Для вас» и «Новинки» без подмешанной рекламы и без напоминаний: ТОП-вставки туда не берутся, ТОП — только на общих основаниях и с пометкой; в ленте с «Для моего» ТОП — только подходящий и с пометкой (5.1.2 — данные «Моего» не выбирают рекламу) |
| Покупки | только физический товар и услуги вне приложения («Апгрейд ПК») через безопасную сделку — вне оплаты Apple (3.1.3(e)); стандарты, «Что почём», подсказки и «Для вас» бесплатны и ничего цифрового не продают; ТОП — по-прежнему только StoreKit |
| Бренды в каталоге | IKEA, Nespresso, LEGO, Apple — только как указание совместимости («совместимо с …»), без логотипов и намёка на официальность; ISO, IEC, ГОСТ — номером, текст стандартов не копируем |

Политика на kliko.kz — текст в договоре (§10.7), до включения серверных частей.

`rim`, `size`, `device_model`). Новые семьи — только в каталоге. Один словарь синонимов постепенно заменяет разбросанные

**С идущими пачками** («скорость», «колёса», «мерки») — код `Sources` сейчас не трогаем. `WheelStandards.swift`,

запросов нет, «Для вас» — после рядов главной, каталог — статический снимок.

## 11. Порядок работ — по пользе, каждая пачка полезна сама

После выхода трёх пачек («скорость», «колёса», «мерки»). Каждый шаг — со своим рубильником `Config.*` и флагом
`rules.std.*`.

| Пачка | Что | Польза без сервера | Нужен сервер |
|---|---|---|---|
| 1. Ядро | `StandardsModel`, `Catalog`, `Normalize`, `Match`, `Adapters`; эталоны; «Подходит моему» для новых семей по `specs` и тексту (VESA, цоколь, ОЗУ, SSD, БП, кровать, матрас, бельё, зарядки, платформы АКБ, автокресла — из текста не выше «Проверьте») | плашка на всех семьях | — |
| 2. «Мой компьютер» и апгрейд (акцент владельца) | раздел, снимок экрана и наклеек, `StandardsUpgrade`; цены — «от X ₸» по живым объявлениям: телом POST (§7), до того — кнопка «Найти» | «можно так или так» с проверками | `std` и `q` в теле POST; цены по стандарту — позже (`std.price`) |
| 3. Подача | блок «Параметры», шаблоны, «Нашли в названии», камера, `qty`, строка «Параметры: …» | продавец ставит стандарт за касание | `std.store` — поля вместо строки |
| 4. «Мой дом» | кровать, лифт, цоколи, VESA, техника по модели; «Пройдёт ли?» в `FitBox`; чип «Для моего …» по загруженному | подбор постели, ламп, кронштейнов | `fit_std` — по всему сайту |
| 5. Двойник | `ВещьМоего`, сделка → «Моё», «Поставили?», «Подошло?», «Продать своё», «Проверить при получении» | цифровизация купленного | снимок и `outcome` (`std.deals`), `from_deal` |
| 6. «Для вас» и «Новинки для моего» | полка на главной, локальные уведомления | рекомендации по «Моему» | `fit_std` |
| 7. Дети, питомцы, спорт, инструменты; чек ОФД | разделы и сверка на телефоне | — | — |
| 8. Серверные включения | по флагам схемы, без сборки: `std=` и фасеты, `price_stats` с `std`, `fit_std`, снимок сделки, `provenance`, справочники, push «Новинок» | — | договор §12 |

Сайту — сразу (договор §12): политика, `api/standards.php`, расширение `E_SPECS`, поля `std`, **перенос старых** — без
него подборки и цены пустые.

## 12. Риски

| Риск | Что делаем |
|---|---|
| Ложное «Подходит» → возвраты и споры | «Подходит» только по полям продавца или подтверждённому скану; из текста — не выше «Проверьте»; «проверили по стандарту, а не по экземпляру»; деталь всегда названа; «Проверить при получении»; причина спора «Не соответствует указанному стандарту» |
| Поколения внутри «стандарта» | разводим каноном и правилами: LGA1700 DDR4 / DDR5 по плате, Apple Watch 42 — две группы, Ryzen 5000 на B450 — BIOS, x8 на PCIe 3.0 |
| Нюансы вне стандарта (QVL ОЗУ, ревизии ноутбуков, длина карты у партнёра) | где зависит от экземпляра — «Проверьте» с тем, что проверить; без FPS и процентов |
| Региональные варианты (картриджи, кровати US / UK / EU, E26 против E27, 110 В) | главный путь — код и маркировка с самой вещи камерой; региональные коды в справочнике с пометкой |
| Безопасность (кресла, электрика, газ, диски болгарки, лампы 12 В) | `safety` в каталоге: никогда «Подходит» по тексту; «по стандарту подходит по росту», а не «безопасно»; б/у кресла — год и «не было в ДТП»; LED в галоген не предлагаем |
| Приватность (опись дома, доход, дети) | всё на телефоне; в сеть — значения стандартов в теле POST; вещи детей, вес и рост — не уходят (обхваты — только прежним `fit_me`); в аккаунте — только подписки «Новинок», включённые вручную; покупки — по согласию |
| Честность цен (цены объявлений ≠ сделок, малые выборки, магазины, накрутка, штука против комплекта) | один голос на продавца, пороги 3 / 8 / 5, Тьюки, `qty`, заморозка, подпись источника и окна, «от» — только живое объявление |
| Тёмные паттерны | «Можно ничего не менять», уведомления выключены по умолчанию и ≤ 1 в день, у подборки есть конец, без «ваш ПК устарел» |
| Объём (115 семей) и дрейф каталога | каталог полный сразу, интерфейс — волнами по пользе; `v`, ETag, только добавление; словарь учится (договор §2.6); владелец каталога — один файл |
| Нагрузка на продавца | всё по желанию, подстановка из названия и камеры, без напоминаний; метрика — доля подач со `std` без падения доли завершённых подач |
| Ошибки распознавания (O/0, S/5, кириллица, «R16» — не радиус) | голоса кадров, притягивание к ряду, подтверждение касанием, эталоны |
| Справочники ноутбуков, плат, техники стоят денег | без них — ввод чипами и камерой; не обещать «всё само» до их появления |
| Сервер отстаёт | всё ключевое работает на телефоне: разбор, сверка, апгрейд на живых объявлениях; без снимка сделки — `?id=` (и данные теряются, если объявление удалено — сказано ultra-site) |
| Конфликт с идущими пачками | только новые файлы; адаптеры после влития; на запуске новых запросов нет |
| Рынок КЗ | праворульные японские машины (JIS-аккумуляторы, свои лампы), товары из США и Китая (110 В, вилки A / B / I), смесь кириллицы, латиницы и казахского, советские стандарты рядом с EN (М500 / ЦЕМ 42,5, A-III / A400) — всё это в словаре синонимов |
