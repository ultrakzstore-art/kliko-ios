# Задание ultra-site: ИИ-поиск — «человек прямо в поисковике видит товары и находит то, что искал»

Владелец, 17.10.2026: «ИИ поиск надо усовершенствовать — чтобы человек прям в поисковике видел рекомендации и нашёл то,
что искал за счёт ИИ, то есть ИИ должен знать все товары по сайту». На план — «Да напиши, задание + живые товары в
подсказках, все 4 порядка».

Приложение iOS (сборка 85) уже показывает **живые товары в подсказках** через нынешний `api/listings.php?q=` (рубильник
`search_live`). Всё, что ниже, — сервер; приложение читает новые поля терпимо: нет поля — работает как сейчас.
Включение новой двери в приложении — рубильник **`ai_search`** (по умолчанию выключен; внести в белый список
`inc/app_remote_config.php` вместе с `search_live`). Приложение слушает оба рубильника **со сборки 86**; в 85 их нет
в белом списке приложения — там живые товары всегда идут через `api/listings.php`, а `ai_search` не включится.

## 0. Принципы

* **ИИ не читает сайт на каждый запрос.** «Знать все товары» — это индекс: каждое объявление попадает в него при
  публикации и правке (текст + смысловой отпечаток). ИИ только понимает запрос и, если нужно, переупорядочивает
  первые 20–30 найденных.
* **Быстро:** подсказки — p95 ≤ 120 мс; ИИ-разбор запроса — ≤ 600 мс, иначе обычный поиск без него.
* **Честно и без денег мимо Apple:** поиск только по видимым объявлениям; цифровые — по рубильнику `digital_goods`, как
  в ленте (в приложении не показываются).
* **Приватность:** в ИИ уходит только текст запроса (без аккаунта, телефона, «Моего»); журнал поиска — без личных данных,
  хранение ≤ 90 дней, агрегаты дольше.
* **Цена:** отпечатки — один раз на объявление; разбор запроса — маленькой моделью (Claude Haiku или сопоставимой) с кешем
  нормализованных запросов на 7 дней; дневной потолок расходов в админке, превышен — поиск без ИИ.

## 1. Порядок 1 — индекс и подсказки с товарами

**Индекс всех объявлений.** Документ на объявление: `id`, название, раздел и путь раздела, бренд, модель, характеристики
(`std`, `parts`, `size_all`), цена, город/регион, состояние, дата, `is_top`, признаки доверия, обложка. Обновлять при
`submit`, `edit_item`, снятии, продаже, удалении (очередь, не в запросе пользователя).

Движок — на выбор сайта; рекомендуем **Meilisearch** (свой сервер, бесплатно): опечатки, синонимы, фасеты, гибридный
поиск с отпечатками «из коробки». Запасной путь — MySQL FULLTEXT + триграммы.

Нормализация запроса и документа (одна функция):
* регистр, ё→е, лишние знаки; **раскладки и транслит** ru/kk/en (`айфон`=`iphone`, `самсунг`=`samsung`, «ноут»=«ноутбук»);
* казахские буквы ↔ русские близкие (`қ→к`, `ң→н`, `ө→о`, `ү→у`, `ұ→у`, `і→и`, `ә→а`, `ғ→г`, `һ→х`) для совпадений;
* опечатки: расстояние 1 для слов 4–7 букв, 2 — от 8;
* словарь синонимов (стартовый — `MK_SUGG`, бренды из `MK_CATS`, стандарты из `api/standards.php`), дальше — из журнала
  (§4).

**Новая дверь:** `GET /api/search_suggest.php?q=<текст>&lang=ru|kk|en|ar&city=<код>&cat=<раздел?>&limit=5`

```json
{
  "ok": true,
  "q": "айфон 13",
  "q_norm": "iphone 13",
  "did_you_mean": null,
  "total": 12,
  "items": [ /* до limit объявлений в форме items api/listings.php (id, title, price, images, city, cond, …) */ ],
  "cats": [ { "key": "smartphones", "name": "Смартфоны", "path": "Электроника › Смартфоны", "count": 11 } ],
  "brands": [ { "name": "Apple", "cat": "smartphones", "count": 9 } ],
  "queries": [ "iphone 13 pro", "iphone 13 128 гб" ],
  "took_ms": 38
}
```
* `items` — лучшие совпадения с учётом города человека (свой город выше, потом весь Казахстан);
* `did_you_mean` — исправленный запрос, когда по исходному мало (< 3) или ничего;
* кеш 60 с по (`q_norm`, `lang`, `city`, `cat`); ограничение частоты — 10 запросов/с с адреса;
* без куков и без входа.

## 2. Порядок 2 — ИИ понимает запрос

Разбор текста в фильтры: сначала правила (цены «до 300к», «от 50 000», «300-500 тыс»; города и районы из
`geo_kz.json`; «б/у», «новый», «с пробегом»; размеры «M», «42», «205/55 R16»; объём «128 гб»), остальное — модель по
JSON-схеме:

```json
{ "cat": "laptops", "brand": "", "model": "", "price_min": null, "price_max": 200000, "city": "",
  "cond": "", "std": { "ram_gb": 16 }, "size": "", "intent": "учёба", "q_rest": "ноутбук" }
```

* В `search_suggest.php` добавить `chips: [ { "label": "до 200 000 ₸", "param": "pmax", "value": "200000" }, … ]` и
  `ai_q` (что искать текстом после разбора).
* `api/listings.php` принимает **`ai=1`** (приложение шлёт его с `q`, когда `ai_search` включён): сервер сам применяет
  разбор и отдаёт `ai_applied: [ { "label": "до 200 000 ₸", "param": "pmax", "value": "200000" }, … ]` — приложение
  покажет строкой «Kliko AI понял: …» над выдачей. Явные фильтры человека сильнее разбора.
* Кеш разбора — 7 дней по `q_norm`; нет ответа модели за 600 мс — только правила.

## 3. Порядок 3 — смысловой поиск

* **Отпечаток (embedding)** каждого объявления при публикации и правке: название + раздел + бренд/модель + стандарты +
  первые 300 знаков описания. Хранить рядом с индексом (в Meilisearch — встроенный embedder).
* Запрос: **гибрид** — текстовое совпадение + близость отпечатков (доля смысла ≈ 0,4; подобрать по §6).
  «Ноут для учёбы», «подарок девушке до 20к», «что-то для дачи» находят товары без этих слов в названии.
* Для длинных естественных запросов (≥ 4 слов) — **переупорядочить первые 30** моделью с короткой причиной
  `why: "16 ГБ ОЗУ, до 200 000 ₸"` (отдать в `items[].why`, приложение покажет под ценой в подсказке).
* **Ничего не нашлось:** ослаблять по шагам (город → весь Казахстан → цена ±20 % → без состояния) и вернуть
  `relaxed: ["city", "pmax"]` + `items`; приложение напишет «Ничего точно — вот близкое» и предложит «Ищу» (подписка).

## 4. Порядок 4 — учится и знает человека

* `POST /api/search_event.php` (приложение шлёт, когда `ai_search` включён; без входа, `sid` — случайный номер
  установки):
  ```json
  { "sid": "…", "q": "айфон 13", "kind": "suggest_item|suggest_query|chip|did_you_mean|submit", "id": "p…", "pos": 2 }
  ```
* Из журнала: популярные запросы (замена ручного `MK_TRENDS`), синонимы (что ищут → что открывают), поднятие часто
  открываемых по запросу (CTR), «пустые» запросы — в отчёт админки (что люди ищут, а у нас нет → задание продавцам и
  «Спрос», `SERVER_NEW_FOR_MINE.md` §16).
* **«Моё»:** подсказки и выдача принимают то же тело `fit_*`, что лента (`std_server_fit`), — подходящее человеку выше.
  Хранить не нужно.

## 5. Приложение — что уже сделано и что включится само

| Порядок | Приложение | Рубильник |
|---|---|---|
| сейчас | живые товары (до 5) в подсказках через `api/listings.php?q=&per=5`, «Показать все» | `search_live` (вкл.) |
| 1 | вместо этого — `search_suggest.php`: товары, разделы со счётом, бренды, «Вы имели в виду» | `ai_search` |
| 2 | чипы разбора в подсказках; `ai=1` в поиске ленты; строка «Kliko AI понял: …» из `ai_applied` | `ai_search` |
| 3 | `items[].why` под ценой в подсказке; `relaxed` → «Ничего точно — вот близкое» | `ai_search` |
| 4 | `search_event.php` на нажатия в подсказках и поиск | `ai_search` |

## 6. Проверка (приёмка)

| Запрос | Ожидаем |
|---|---|
| `айфон 13` | iPhone 13 первыми; `q_norm` = `iphone 13` |
| `самснуг а54` | «Вы имели в виду: samsung a54» и Samsung A54 |
| `ноут для учебы до 200к` | ноутбуки ≤ 200 000 ₸, чип «до 200 000 ₸» |
| `куртка зимняя M` | верхняя одежда, размер M |
| `шины 205 55 16` | tires-wheels, `std` 205/55 R16 |
| `диван угловой алматы` | диваны, Алматы выше |
| `арзан ноутбук` (kk) | ноутбуки по возрастанию цены |
| `подарок девушке до 20к` | смысловой поиск: украшения, косметика, цветы ≤ 20 000 ₸ |
| пусто по точному | `relaxed` + близкое |

Цели: p95 подсказок ≤ 120 мс; доля запросов с хотя бы одним нажатием в подсказках — растёт неделя к неделе; доля
«ничего не нашлось» ≤ 5 %.

## 7. Порядок работ и сроки

1. Индекс + `search_suggest.php` (порядок 1) — ~1 неделя.
2. Разбор запроса правилами + моделью, `ai=1`, `ai_applied` (порядок 2) — ~1 неделя.
3. Отпечатки, гибрид, переупорядочивание, ослабление (порядок 3) — ~1–2 недели.
4. Журнал, синонимы, CTR, отчёт «что ищут, а нет» (порядок 4) — ~1 неделя.
