# Размеры одежды и обуви «как на бирке» — что нужно от сайта и сервера

Документ для разработчика сайта kliko.kz (ultra-site), 14.10.2026. Слова владельца: «при подаче вещей размеры
совмещённо, как в магазинах: стандарты EU 29 | MEX какой-то вещи, обувь — всё, что можно»; «шаблоны, чтобы готовые
были»; «задействуй реальные образцы, которые могут быть»; «задание для сайта такой же — при подаче это должно работать
как надо: **человек должен получать дофамин от подачи до просмотра чужих предложений**». Общие требования: удобно для
глаз, ровная схема, мощная анимированная подача, летает на всех девайсах.

Зачем: на бирке у продавца «EU 42», а покупатель знает свой «US 9» или «RU 41». Сейчас в поле «Размер» одно число без
системы, и покупателю приходится гадать. В приложении 1.12 поле «Размер» у одежды и обуви заменено блоком «как на бирке»:
продавец выбирает размер в своей системе, остальные системы считаются по таблице. В поле уходит значение в системе сайта,
а все системы — строкой в описание. От сайта нужно: те же таблицы, хранение всех систем, такой же выбор в форме и бирка у
покупателя.

| Что | Где | Кто |
|---|---|---|
| Блок «Размер»: вкладки, системы, сетка, бирка | подача и правка в приложении | **готово** (1.12, сборку проверяет CI) |
| Значение поля `storage` в системе сайта | приложение | готово; сервер: подтвердить систему (2.1) |
| Строка «Размер: EU 42 · RU 41 · …» в конце описания | приложение, **временно** | сервер: ничего; после `store` — по желанию убрать (2.4) |
| Таблицы и разделы в схеме: `rules.sizes` | `api/app_post_schema.php` | сервер (1.3); приложение прочтёт со следующей сборки |
| `size_sys` · `size_all` в `submit` и `edit_item` | приложение — следующая сборка, после `rules.sizes.store` | сервер: принять и хранить (2.2) |
| Отдача `size_sys` · `size_all` | `api/listings.php`, `my_items` | сервер (2.5) |
| Тот же выбор в форме | кабинет сайта | сайт (раздел 3) |
| Бирка у покупателя, чип на карточке | окно объявления, лента | сайт (4); в приложении вид готов, встраивается |
| Фильтр ленты в любой системе: `size=` | `api/listings.php` | сервер (4.3) |
| «Дофамин» от подачи до чужих предложений | сайт и приложение | сайт (раздел 5) |

## 1. Единые таблицы

Одни на всё: приложение, форма сайта, бирка покупателя, фильтр ленты. Таблицы проверены 14.10.2026 по таблицам Nike и
Converse, Lamoda и Wildberries, ASOS и Zalando, H&M, Zara и Carter's, по ISO 8653 (кольца), New Era (кепки) и EN 420
(перчатки). У брендов бывает ±½ размера, поэтому на бирке везде есть мелкая оговорка.

### 1.3. Отдавать сервером: `rules.sizes`

Предлагаем отдавать таблицы и разделы в схеме подачи `GET /api/app_post_schema.php`, рядом с `rules.fit`. Тогда таблицы
правятся на сервере без новой сборки, и сайт с приложением не расходятся.

```json
{
  "ok": true,
  "v": "2026-10-14-3",
  "rules": {
    "sizes": {
      "on": true,
      "store": false,
      "tables": [
        { "key": "shoes_kids", "title": "Детская обувь",
          "systems": ["EU", "RU", "US", "UK", "MEX", "CM"], "site_system": "EU",
          "rows": [["16", "16", "1C", "0.5", "9", "9"], ["29", "29", "11.5C", "11", "18", "18"], "…"],
          "note": "C — малыши, Y — школьники; MEX — сантиметры" },
        { "key": "shoes_women", "…": "…", "prefer": { "US W|6.5": 5, "UK|4.5": 6, "MEX|23.5": 5, "CM|23.5": 5 } }
      ],
      "cats": {
        "womens-shoes": ["shoes_women", "shoes_men", "shoes_kids"],
        "mens-shoes": ["shoes_men", "shoes_women", "shoes_kids"],
        "womens-clothing": ["clothes_women", "jeans", "bra"],
        "kids-clothing": "kids_height",
        "rings": "ring"
      }
    }
  },
  "fields": {
    "kids-clothing-0-12": [
      { "key": "storage", "type": "select", "label": "Возраст", "size_sys": "Возраст", "options": [{ "v": "…" }] }
    ]
  }
}
```

- `tables[]` повторяет 1.2: `key`, `title` и `note` на языке запроса, `systems` — коды столбцов, `rows` — строки,
  `site_system`. Коды систем — как на бирках, не переводятся: `EU`, `RU`, `US`, `US W`, `US M`, `UK`, `MEX`, `INT`,
  `EU/DE`, `US/UK`, `RU/EU`, `IT`, `FR`, `W`, `L`. `CM` — сантиметры, `Возраст` — возраст, код с «, см» — мерка тела.
- `prefer` (по желанию) — значение повторяется в соседних строках, какую строку брать (номер с 0). Сейчас нужен только у
  `shoes_women`, это строки Nike.
- Пары: `jeans` с `jeans_length` дают «W32 L32», `bra` с `bra_cup` — «75B». Пары приложение собирает по ключам, остальные
  таблицы простые.
- `cats` — раздел → ключ таблицы или список ключей. Список — это вкладки в том же порядке, первая открыта сразу. Значение
  наследуется вниз по дереву, ближайший узел главнее. Пустой список — блока нет, поле обычным списком.
- `size_sys` у поля `storage` в `fields` раздела — в какой системе значение поля (2.1). Если ключа нет — `site_system`
  первой таблицы раздела.
- `on: false` — блок выключен везде. `store: true` — сервер принимает, хранит и отдаёт `size_sys` и `size_all`
  (раздел 2). С ним приложение перестаёт писать строку в описание. Ставить последним, когда 2.2 и 2.5 уже работают.
- Таблицы поменялись — сменить `v` схемы: ETag изменится, приложения подхватят без новой сборки.
- Как приложение берёт таблицы: таблица с тем же `key` заменяет встроенную, новый `key` — простая таблица. Нет
  `rules.sizes` — встроенные таблицы и разделы 1.1. **Приложение 1.12 читает только встроенные:** `rules.sizes` и
  `size_sys` начнёт читать следующая сборка, после того как вы подтвердите формат.

Шины, диски и диагонали экранов — не здесь, а в шаблонах размеров (`rules.dims`, договор `docs/SERVER_SIZE_TEMPLATES.md`).

## 2. Поле размера и хранение

### 2.1. В какой системе значение поля `storage`

Поле размера — слот `storage`: фасет «Размер» в корнях `clothing` и `sport`, «Возраст» в корне `kids`. По нему отбирает
лента, поэтому в поле остаётся **одна** система — система сайта, столбец «Значение поля» в 1.1. Варианты поля на сайте мы
сверить не смогли: kliko.kz из песочницы закрыт. Поэтому систему мы выбрали по устройству поля.

**Что нужно от вас:** подтвердить систему по разделам 1.1 или указать `size_sys` у поля в схеме и прислать нынешние
варианты поля по этим разделам. Подпись поля тоже работает: «Размер (EU)» — EU, «Возраст» — возраст. Главный риск: если у
одежды в поле окажутся EU-числа без подписи, RU 46 ляжет в EU 46, а это разные размеры.

Как приложение ставит значение в поле (форма сайта — так же, раздел 3):

1. Кандидаты по порядку. Сначала значение в системе поля: у пары — целиком «75B», потом без второй части «75»; у
   «44–46» — ещё меньшее, «44». Потом буква INT, потом возраст. Числа других систем не берутся: RU 40 и EU 40 у одежды —
   разные размеры.
2. Поиск среди вариантов поля по шагам: точное совпадение (`v` или `l`); слово внутри подписи («46 (M)», «EU 42»);
   ближайшее число не дальше 1 (37.5 → 37, при равенстве — меньшее). Для возраста — вариант, в диапазон которого попадает
   середина («7–8 лет» → «7-10 лет»), или ближайший не дальше года.
3. Ничего не нашлось — своё значение в системе поля, если поле это разрешает (`other`). Иначе поле остаётся пустым, и
   продавец выбирает из списка сам.
4. Сравнение без учёта регистра; «,» = «.»; любое тире = «-»; кириллические двойники = латиница («М» = «M», «ХL» = «XL»,
   «75В» = «75B»).

### 2.2. `submit` и `edit_item`: `size_sys`, `size_all`

Два необязательных поля. Приложение начнёт их слать, когда в схеме появится `rules.sizes.store: true`:

```json
{ "category": "mens-shoes", "storage": "42", "size_sys": "US M",
  "size_all": "EU 42 · RU 41 · US M 8.5 · UK 7.5 · MEX 26.5 · 26.5 см", "…": "остальные поля как раньше" }
```

- `size_sys` — система, в которой выбирал продавец, то есть код столбца таблицы («US M», «W», «RU/EU», «Возраст»).
  Покупатель видит её на бирке крупно. Незнакомый код не сохранять.
- `size_all` — все системы строкой, точно как строка описания без «Размер: » (формат — 2.3). Одна строка, до 200 знаков.
  Разбирать как хвост строки 2.3 (делить по «·» или «|», узнаны хотя бы два куска); не разбирается — не сохранять.
  Отказывать в подаче из-за этих полей не нужно.
- `storage` — как раньше, в системе сайта (2.1).
- `edit_item`: поле пришло пустым — размер снять; поля нет (старое приложение, раздел без размера) — **прежние значения не
  трогать**.
- Kliko AI (`recognize`, `accept_draft`): если размер прочитан с бирки на фото («EU 42 / US 9 / UK 8»), можно отдать
  `storage` и `size_sys`. Угадывать размер по фото нельзя.

### 2.3. Строка в описании — пока сервер не хранит

Пока в схеме нет `rules.sizes.store: true`, приложение через пустую строку дописывает **последней строкой** описания:

```
Размер: EU 42 · RU 41 · US M 8.5 · UK 7.5 · MEX 26.5 · 26.5 см
```

Образцы по таблицам (из кода приложения; разбор ниже проверен на строках всех вариантов таблиц):

| Таблица | Строка |
|---|---|
| `shoes_women`, EU 38 | Размер: EU 38 · RU 37 · US W 7 · UK 4.5 · MEX 24 · 24 см |
| `shoes_kids`, EU 29 | Размер: EU/RU 29 · US 11.5C · UK 11 · MEX 18 · 18 см |
| `clothes_women`, M | Размер: INT M · RU 46 · EU/DE 40 · US 8 · UK 12 · IT 44 · FR 42 |
| `clothes_men`, L | Размер: INT L · RU/EU 50 · US/UK 40 · IT 50 |
| `jeans` женские, W30 L32 | Размер: W30 L32 · RU 46 · INT M |
| `bra`, 75B | Размер: RU/EU 75B · UK/US 34B · FR 90B · IT 3B |
| `kids_height`, 128 | Размер: EU/RU 128 · 7–8 лет · US 7 |
| `ring`, 17 | Размер: RU 17 · US 6.5 · UK M½ · EU 53 |
| `hat`, 57 | Размер: RU 57 · INT M · US 7 1/8 · UK 7 |
| `gloves`, 8 | Размер: RU/EU 8 · INT M |

- Системы идут в порядке столбцов таблицы. Одинаковые соседи склеены через «/» («EU/RU 29»), а «см», возраст и W не
  склеиваются.
- Строка всегда по-русски, как «Габариты (Ш×В×Г): …». Разделитель — « · », разбор понимает и «|».
- Как разбирать. Строка — `^\s*(?:Размер|Size)\s*:\s*(.+?)\s*$` (многострочно, без учёта регистра). Хвост делится по
  «·» или «|». Кусок узнаётся, если он:
  - сантиметры: `^\d+(?:\.\d+)?\s?(?:см|cm)$`;
  - джинсы: `^W\d+(?: L\d+)?$`;
  - код и значение: `^([A-Z]{2,3}(?: [WM])?(?:/[A-Z]{2,3}(?: [WM])?)*) (\S.*)$`;
  - возраст: есть «мес», «год» или «лет».
- **Наша** строка — та, где узнаны хотя бы два куска. Строку продавца «Размер: 42, маломерит» не трогать.
- При правке приложение вынимает строку из текста и ставит одну свежую, поэтому строки не копятся. Описание вместе со
  строкой — не длиннее 5000 знаков.
- Раздел или название сменились, и строка им больше не подходит (не одежда и не обувь, ремни, другие таблицы: обувь →
  головные уборы) — приложение убирает её из описания. Те же таблицы (женская обувь → мужская) — строка остаётся. Сброс
  размера («×» на бирке) тоже убирает строку.
- В минимум описания (10 знаков) эта строка **не** засчитывается: приложение считает длину без неё, чтобы описание из
  одной автоматической строки не проходило. Серверу стоит считать так же (по разбору выше).

### 2.4. После `store: true`

- Новые подачи приходят с `size_sys` и `size_all`, без строки. Если строка всё же пришла **вместе** с `size_all`, её можно
  убрать из описания по разбору 2.3.
- Строка есть, а `size_all` нет (старое приложение, старый кэш схемы) — заполнить `size_all` из строки, без «Размер: ».
  Старые объявления можно перенести так же, фоновой задачей, по желанию.

### 2.5. Отдача

`api/listings.php` (окно объявления) и `cabinet.php?action=my_items` (правка) отдают плоские поля:

```json
"storage": "42", "size_sys": "US M", "size_all": "EU 42 · RU 41 · US M 8.5 · UK 7.5 · MEX 26.5 · 26.5 см"
```

- В ленте — по желанию: эти поля нужны для чипа на карточке (4.2).
- `size_all` отдавать как сохранено, по-русски. «см» и возраст переводят на язык экрана сайт и приложение.
- Если `size_all` нет, а в описании есть наша строка, бирку строят по строке.

## 4. Покупатель: окно объявления, карточка, фильтр

### 4.1. Окно объявления — бирка

Перед описанием — блок «Размер по бирке».

- Крупно — система покупателя (та, что он выбирал последней в фильтре или форме, `localStorage`). Если её нет —
  `size_sys` продавца, иначе система сайта.
- Строкой все системы из `size_all` или из строки описания, мерки тела по таблице и оговорка ±½.
- Нажатие на систему в строке делает её крупной и запоминает.
- Ссылка «Ещё в этом размере» ведёт в ленту раздела с `size=` (4.3) — прямой путь к чужим предложениям.
- Описание показывать без строки «Размер: …»: она уже на бирке.
- В приложении вид бирки готов (`БиркаРазмераОбъявления`, `ClothingSizesView.swift`), в окно объявления его встроят
  следующим шагом.

### 4.2. Карточка в ленте

Чип размера на карточке — одна система, не вся строка: «EU 42». Если покупатель отбирает ленту в другой системе — в ней:
«US M 8.5».

### 4.3. Фильтр ленты в любой системе

Сейчас фасет «Размер» уходит как `stov=46|48`, значения в системе сайта. Это оставить и добавить:

```
GET /api/listings.php?cat=mens-shoes&size=US%20M:8.5|US%20M:9
```

- `size=<код>:<значение>`, несколько — через «|». Код — как в таблицах. `US` без W/M у обуви ищется по всем таблицам
  раздела.
- Форма с таблицей впереди `<таблица>:<код>:<значение>` (размеры разных видов одним запросом) и `size` из «Моего» в
  теле POST — `docs/SERVER_MY_THINGS.md` §3.5, 3.1 (согласовано ultra-site 16.10.2026). Обычный фильтр — в адресе,
  как здесь.
- Сервер по таблицам раздела (`cats`) находит строки, где в столбце кода стоит это значение (сравнение — 2.1, п. 4). Дальше
  отбирает объявления по значению поля в системе сайта (`storage`) и те, у которых этот кусок есть в `size_all`.
- Без раздела (поиск по всей ленте) — по всем таблицам.
- В фильтре сайта над чипами размера — тот же переключатель системы. Выбранная система запоминается, и потом она крупная
  на бирках и карточках.

## 5. «Дофамин от подачи до просмотра чужих предложений»

Приёмы для подачи на сайте; приложение повторит те же. В этой цепочке нет платных предложений и тёмных паттернов.

1. **Мгновенный отклик на каждый выбор** — до 100 мс и без ожидания сети: чип загорается, бирка пересобирается, у шага
   появляется галочка. Таблицы и схема берутся из кэша (ETag), сеть нужна только при отправке.
2. **Видимый прогресс** — полоса шагов заполняется плавно, галочка у шага появляется, как только готовы обязательные поля.
   Вместо «Ошибка» — «Осталось 2 поля» и переход к первому из них.
3. **Готовые шаблоны вместо пустых полей.** Размер — сеткой, а не вводом. Название по шаблону из выбранного («Кроссовки
   Nike, EU 42»). Фразы-чипы для описания («Носили один сезон», «Без дефектов», «Маломерит на ½», «Есть коробка»)
   вставляются по нажатию, текст можно править. Последние система и вкладка подставлены заранее.
4. **Мягкие ошибки** — прокрутка к полю и подсказка, что сделать. Без красных стен и без сброса введённого.
5. **Праздник публикации** — один раз, до 1.2 с: галочка рисуется (`stroke-dashoffset`), лёгкий всплеск из 12–16 точек,
   карточка объявления въезжает в лист. Без звука; при `prefers-reduced-motion` — только галочка.
6. **Сразу «Похожие у других продавцов»** — в листе «Опубликовано» ряд из 6–10 карточек того же раздела и размера
   (`size=`): сначала свой город, свои объявления не показываются. Без сравнения цен и советов «снизьте цену».
7. **«Ваше объявление увидят …»** — честное число: сколько человек за 7 дней смотрели этот раздел в городе (с этим
   размером, если он есть) плюс совпавшие сохранённые поиски, которым придёт уведомление. Округлять вниз («больше 120»).
   Меньше 20 — без числа: «Сообщим, как только кто-то напишет».
8. **Первые просмотры** — одно уведомление в первый день («Ваши кроссовки посмотрели 12 раз»), не больше одного на
   объявление.
9. **Летает на всех устройствах.** Анимации только на `transform` и `opacity`, без перерасчёта раскладки. Заготовки
   (skeleton) той же высоты, что настоящие блоки. Чипы — обычный HTML без библиотек. Цель — 60 кадров и на дешёвом Android.

**Нельзя:** выдуманные счётчики («23 человека смотрят сейчас»); таймеры и «осталось 2 часа»; заранее отмеченные платные
опции; ТОП и продвижение первым делом в листе «Опубликовано»; стыжение («Нет, я не хочу продать быстрее»); «Готово»,
спрятанное за «Поделиться»; звук и вибрация без действия человека.
