# «Свой ИИ» во всех местах приложения — покрытие и что нужно от сервера

Документ для разработчика сайта kliko.kz (ultra-site) и владельца. Просьба владельца (13.10.2026): «что бы сторонние
API ии работали во всех местах так же … и так же всё в iOS».

Основа — ответ ultra-site по «Своему ИИ» от 08.10.2026 (вариант Б: свой ключ поставщика в кабинете, Premium «Свой ИИ»,
рубильники `own_ai`, `own_ai_openrouter`; код сайта — `inc/own_ai.php`, `inc/cabinet/own_ai.php`,
`js/cabinet-settings.js cabOwnAi()`). В приложении он описан в `Sources/Native/OwnAI/OwnAIModel.swift`; ниже ссылки
«§N» — на разделы того ответа.

Часть **А** — где в приложении сейчас зовётся ИИ сайта и работает ли там свой ИИ. Часть **Б** — предложение договора:
свой ИИ в новых местах (в приложении уже сделано, но выключено рубильником). Часть **В** — вопросы к ultra-site.

## 0. Что проверяли в каждом месте

| Вопрос | Как должно быть по договору |
|---|---|
| (а) `own:1` | Нужен только у `recognize` (§5). Остальным ИИ-функциям сервер сам применяет свой ИИ по сессии. Глубокого разбора (`paid:1`) в приложении нет, поэтому пара `paid:1` + `own:1` не нужна. |
| (б) отказ своего ИИ | Разбирается `ОтказСвоегоИИ.из` (OwnAIModel.swift): `own_ai:"<код>"`, `own_ai_gone:true`, `error:"own_ai"`. Готовый текст берётся из первого человеческого поля `msg` → `error` → `text` → `ai_msg` (§5). Для `premium` и `gone` приложение пишет свою фразу: у сайта эти тексты могут звать к покупке с баланса или к пробному периоду, а это нарушает App Review 3.1.1. Показ — окно `ОкноСвоегоИИ.показатьОтказ` с кнопкой «Настройки своего ИИ», а для `key`, `funds`, `model`, `gone` ещё и «Выключить свой ИИ» (`own_ai_use {on:false}`). Для живых и фоновых запросов — `СвойИИМодель.сказатьОдинРаз`: одно окно на код за запуск. |
| (в) сессия | Свой ИИ работает только с сессией кабинета, с Bearer-токеном идёт через Kliko AI (§4). **В приложении Bearer не используется ни в одном запросе** (`git grep Bearer` находит только образцы кода 1С, которые показываются человеку на экране интеграций). |

Транспорты, через которые идут ИИ-запросы:

- **`КабинетСайта.вызвать`** (`МоиОбъявленияAPI.отправить` / `ИнбоксAPI.отправитьБезТокена`) — `fetch` изнутри скрытой
  страницы kliko.kz: кука `kliko_cab`, настоящие `Origin`/`Referer`, `csrf` в теле. Если включён рубильник
  `Config.нативнаяСессия` (сейчас выключен), запрос идёт через URLSession с теми же куками из WebKit. Для `chat.php` и
  `dm.php` тогда — без `Origin`/`Referer`, с заголовком `X-Kliko-Csrf` (правки сервера 92–94, 97–99).
- **`ИмпортAPI.форма`** — multipart `fetch` изнутри той же страницы: та же кука и тот же токен.
- **`ПоискПоФотоAPI.отправить`** — URLSession, заголовок `Cookie` со всеми куками kliko.kz из WebKit (среди них
  `kliko_cab`) и `csrf` страницы в теле. Подставных `Origin`/`Referer` нет.

## Б. Договор-предложение: свой ИИ в новых местах

**Статус в приложении.** Всё сделано и выключено рубильником `Config.свойИИНовыеМеста = false`
(`Sources/Native/OwnAI/OwnAIPlaces.swift`). Пока рубильник выключен или сервер не прислал `own_ai.places`, на экране
«Свой ИИ» ничего не меняется. Всё ниже — только **добавления** к договору 08.10.2026, ничего существующего не меняется.

### Б.1. `own_ai_run` во всех успешных ИИ-ответах

Сейчас `own_ai_run` есть только у `recognize`. Просим добавить его в **каждый успешный ответ** ИИ-функции, где сработал
свой ИИ: `ai_replies`, `ai_replies_dm`, `ai_service`, `photo_search`, `shot_read`, `ai_import`, `ai_job_chunk`,
`kp_generate`, `ai_resume`, `ai_style`, `translate`, `consult`, а также в `tryon status` (там оно уже записано как
необязательное).

- Значение: `1`, `true` или строка режима (`"fast"`, `"deep"`). Нет поля, `0`, `false` — работал Kliko AI.
- Приложение по нему пишет «через ваш ИИ» (`ОтветСвоегоИИ.своим`). Угадывать по последнему известному `own_ai.active`
  приложение не будет: состояние может быть устаревшим, а подпись должна быть честной.

### Б.2. Места по желанию человека: `own_ai.places` и `own_ai_place`

В объект `own_ai` добавляется массив `places` — где ещё человек может включить свой ИИ:

```json
"places": [
  {"id": "assist",   "label": "Ассистент в чате по вашим объявлениям", "on": false, "avail": true,  "why": ""},
  {"id": "explain",  "label": "Объяснения о товаре",                     "on": true,  "avail": true,  "why": ""},
  {"id": "support",  "label": "Ответы ИИ-поддержки",                     "on": false, "avail": true,  "why": ""},
  {"id": "tryon",    "label": "Примерочная одежды",                      "on": true,  "avail": false,
   "why": "Anthropic — Claude не рисует картинки: примерочная работает на Kliko AI."},
  {"id": "studio",   "label": "ИИ-фоторедактор техники",                 "on": true,  "avail": true,  "why": ""},
  {"id": "precheck", "label": "Предпроверка объявления перед отправкой", "on": false, "avail": true,  "why": ""}
]
```

| Поле | Смысл | Что делает приложение |
|---|---|---|
| `id` | Место. Список закрытый: `assist`, `explain`, `support`, `tryon`, `studio`, `precheck`; новые — добавлением | Порядок строк — порядок сервера; повтор `id` пропускается |
| `label` | Готовая подпись на языке человека | Показывает как есть. Пусто — своя подпись для известного `id`, неизвестный `id` без подписи не показывается |
| `on` | Здесь отвечает свой ИИ | Положение переключателя |
| `avail` | Поставщик и модель это умеют. Нет поля — умеют | `false` — переключатель серый, под ним `why` (пусто — своя фраза «Ваш поставщик или модель этого не умеют — здесь работает Kliko AI») |
| `why` | Готовый текст: почему нельзя | Показывает как есть |

Действие — тем же транспортом, что остальные `own_ai_*` (POST `cabinet.php?action=own_ai_place`, JSON, `csrf`, только
сессия кабинета):

```
own_ai_place {csrf, place:"<id>", on:true|false} → {ok:true, own_ai} | {ok:false, code, error, own_ai}
```

- В ответе — **новый объект `own_ai`** с обновлёнными `places`. Приложение берёт состояние оттуда, своего «ожидаемого»
  значения не держит.
- Без Premium — `{ok:false, need_premium:true, code:"premium", error, own_ai}`, как у `own_ai_connect`. Приложение пишет
  свою фразу без цены и без покупки на сайте, Premium в приложении — только товаром App Store.
- `place` неизвестен или `avail:false` → `{ok:false, code:"place", error}`.
- Блок мест показывается только когда ключ подключён (`connected`). `places` можно не присылать, пока `on:false` у
  всего раздела.

### Б.3. Что сервер включает в каждом месте

Общее для всех мест: свой ИИ берётся, только если раздел `own_ai` включён, Premium действует, `use:true`, ключ рабочий
**и** место включено (`on:true`). Если ключ сломался, переключения на Kliko AI нет (как в §6): отказ `own_ai` с
кодом и готовым текстом. Если место выключено или `avail:false` — работает Kliko AI, как сейчас, и это не ошибка.
Лимиты частоты остаются, квоты Kliko AI снимаются, как в §6.

| Место | Что это | Поставщики | Что важно |
|---|---|---|---|
| `assist` | Ассистент **продавца** в чате по объявлению (`chat.php send` → `ai_reply`) — отвечает покупателям от имени продавца | Все текстовые | Решает **продавец** — его ключ, его объявления. Системная инструкция и фильтры безопасности Kliko остаются те же: без контактов вне площадки, без предоплат, без ссылок на оплату. Ответ проходит тот же фильтр, что ответ Kliko AI. Покупатель видит прежнюю подпись «ассистент продавца» — какой ИИ отвечает, ему знать не нужно. Свой ИИ отказал — покупателю молча нет ответа ассистента (как при выключенном ассистенте), продавцу — `err`/`err_text` в `own_ai` и окно при следующем открытии. |
| `explain` | Объяснения о товаре для **покупателя** («что это за модель», «на что смотреть») | Все текстовые | Ключ покупателя, его вопрос. Отказ — `own_ai:"<код>"`, текст в `error` (как `ai_style`). |
| `support` | ИИ-ответы поддержки (если они появятся) | Все текстовые | Только справка по правилам площадки: инструкция и база знаний Kliko. Денег, возвратов, споров, блокировок ИИ не решает и сразу передаёт человеку. По умолчанию `on:false`. |
| `tryon` | Примерочная (`docs/SERVER_TRYON.md`) | Только с правкой изображений: OpenAI `gpt-image-1`, Google `gemini-2.5-flash-image`, OpenRouter — только модель с выдачей картинок | По `SERVER_TRYON.md` §6 сервер и так берёт свой ИИ, если поставщик рисует. `tryon` в `places` — чтобы человек мог **не** отправлять фото своего тела своему поставщику. По умолчанию `on:true`, `avail` — по умению поставщика. Согласие перед первой отправкой называет поставщика (`ai` в `info`), App Review 5.1.2(i). |
| `studio` | Серверный ИИ-фоторедактор техники (генеративный фон, ретушь) — **если** он появится. Сейчас студия работает на телефоне | Только с правкой изображений | Без сервера места нет. Отказ — как у `tryon`. |
| `precheck` | Предпроверка объявления **до** отправки: «что поправить, чтобы прошло» | Все текстовые | Только подсказка. Решение принимает модерация Kliko AI (Б.4). Ответ — список замечаний, на статус объявления он не влияет. |

### Б.4. Модерация своим ИИ — никогда

Решение «пропустить / отклонить / заблокировать» (`ai_check`, `ai_issues`, `ai_blocked`, `mod_recheck`) должно
оставаться на Kliko AI при любых настройках. Ключ и модель выбирает сам продавец. Через OpenRouter можно поставить
«мягкую» модель или свою инструкцию — и пропустить запрещённое (оружие, лекарства, подделки). Это риск для площадки и для
App Review (1.1, 1.4). Поэтому в `places` нет `moderation`, только `precheck`. Приложение пишет об этом на экране
«Свой ИИ»: «Модерация объявлений всегда работает на Kliko AI — свой ИИ её не заменяет». Эта строка заменяет прежнюю,
когда сервер даёт включить ассистента.

### Б.5. Формат отказов в новых местах

Единый, как у `ai_style` и `photo_search` (§5): `{ok:false, own_ai:"<код>", error:"<готовый текст>"}`. Коды — те же,
что «при работе» (`key`, `funds`, `rate`, `limit`, `model`, `down`, `empty`, `bad`, `gone`). Для мест с картинками
добавляется `images`: поставщик или модель не рисуют. Его нужно отдавать, только если человек сам выбрал свой ИИ для
картинок, а модель сменилась на текстовую. В остальных случаях — `avail:false` и Kliko AI. Приложение разбирает отказ
`ОтказСвоегоИИ.из` / `ОкноСвоегоИИ.показатьЕслиОтказ`. Для `premium` и `gone` приложение пишет свою фразу, без цен и
без пробного периода.

### Б.6. Что включить на ultra-site — по шагам

1. `own_ai_run` во всех успешных ИИ-ответах (Б.1). Можно сразу — это только добавление поля.
2. `own_ai.places` и `own_ai_place` (Б.2); хранение — флаги места в настройках «Свой ИИ» пользователя.
3. Места по готовности функций: `tryon` — вместе с `/api/tryon.php`; `assist` и `precheck` — через существующие
   `chat.php send` и проверку объявлений, с фильтрами Kliko; `explain`, `support`, `studio` — когда появятся сами функции.
4. Сообщить владельцу приложения — он включит `Config.свойИИНовыеМеста`. До этого приложение поле `places` не читает
   на экране, а разбор отказов работает уже сейчас.

## В. Вопросы к ultra-site

1. **`kp_generate`**: в §5 нет формата отказа своего ИИ. Приложение разбирает общий (`own_ai:"<код>"`, текст в
   `error` / `msg` / `text`). Подтвердите формат или назовите свой. И про `quota` (сколько Kliko AI-генераций КП
   осталось сегодня): при своём ИИ она не тратится — присылать её как есть или `null`?
2. **`chat.php` по нативному транспорту.** При включённом `Config.нативнаяСессия` запросы `ai_replies` /
   `ai_replies_dm` идут URLSession-ом с кукой `kliko_cab` и заголовком `X-Kliko-Csrf`, без `Origin`/`Referer` (правки
   92–94, 97–99). Это «сессия кабинета» для своего ИИ, а не Bearer? Сейчас рубильник выключен, запросы идут `fetch`
   страницы — тут вопросов нет.
3. **`ai_off` при своём ИИ.** Если Kliko AI выключен на сайте, а у человека действует свой ИИ — `ai_replies`,
   `ai_import` и `recognize` работают через его ключ или тоже отвечают `ai_off`? Приложение показывает на `ai_off`
   окно «Kliko AI выключен» — при своём ИИ это неверно.
4. **`ai_job_chunk` + `ai_msg`**: приходит ли вместе с ним `own_ai:"<код>"`? Сейчас приложение считает любой `ai_msg`
   отказом своего ИИ (код `bad`, кнопки «Выключить» нет). С кодом окно будет точнее.
5. **`recognize` + `ai_down` при активном своём ИИ**: приложение показывает это как отказ своего ИИ с кодом `down`.
   Если таймаут был у поставщика человека, лучше присылать `own_ai:"down"` — тогда угадывать не придётся.
6. **«Войти через OpenRouter»** (`own_ai_or_start`) по-прежнему не включаем: нужна одноразовая ссылка с `ott` и возврат
   на `kliko://own_ai` (сессии кабинета в браузере нет) — как у входа через соцсети (`app_link`).
